# 开发日志与任务书

这份文件有两个用途：上半部分是**给接手的人看的规矩**，下半部分是**做过什么、为什么这么做**的流水账。

派工出去之前，任务书写在这里；做完之后，结论也记在这里。任何人（包括子代理）动手之前先读完「不可违背的前提」和「怎么算做完」。

## 不可违背的前提

这几条是整个引擎的地基，任何改动都不许绕过。绕过了，测试会当场报错，但更要紧的是：**你会把这个产品变回一个聊天框**。

1. **事件是唯一的事实来源。** 状态只能由 `applyEvent` 从事件算出来，任何地方都不许直接改 `GameState` 的字段。想改状态，就产生一条事件。
2. **先裁定、先提交，然后才轮到叙述。** 骰子在提交那一刻就定死了；叙述失败、模型超时、体检不过，都不影响已经落下的事实。
3. **模型不是裁判。** 它只做两件事：把玩家的话认成意图（给的编号还要过在场检查），把已经提交的事实讲成人话。它说了不算。
4. **防泄底靠结构，不靠提示词。** 玩家此刻感知不到的东西，压根不进模型的上下文。守秘人备注、没拿到的秘密线索、藏着的道具，一律不出现在提示词里。
5. **可见性是资料包的字段，不是引擎的暗规。** 判定口径只有 `itemVisibility` 一处。详见 [`src/data/packs/SPEC.md`](src/data/packs/SPEC.md)。
6. **重放必须一致。** 拿事件记录从初始状态重放一遍，状态哈希必须和当场的状态相同。任何改动之后 `bun run smoke` 都要绿。
7. **回滚不抹历史。** 回到某一版是分出一条新分支，旧分支一个字都不动。

## 写代码的规矩

- **注释只写「为什么」**，不写「这行做了什么」。代码能说清的事不要用注释重复一遍。
- **中文写作要像人话**，不要翻译腔：主语别乱丢，别堆四字短语，别写「进行一个……的操作」。
- 不用 emoji。
- 报错和提示要说清楚**下一步该干什么**，不要只说「出错了」。
- 沿用现有格式：两空格缩进，100 列换行，`@/` 指向 `src/`。
- 新增依赖前先问一句值不值得——这个 Demo 到现在只有四个运行时依赖。

## 怎么算做完

下面五条全绿才算做完，缺一条都不算：

```bash
cd demo
bunx tsc --noEmit -p tsconfig.json   # 类型
bun run pack:lint                     # 资料包体检，含体检自身的自检
bun run smoke                         # 金样冒烟（含 pack:lint 与 keeper:check）
bun run store:check                   # 持久化：不可修改、重放、分支、导出导入
bun run build                         # 真的能打出包来
```

改了界面的，还要在浏览器里自己点一遍（`bun run dev`），不能只看类型过了就交。

# 流水账

## 2026-08-18 · 系统提示把存档刷屏了

**现象。** 「已续上上一场……」在叙述列里刷了几十条，一模一样。

**根因。** 这条提示被当成对话存进了库。于是每次打开：先把库里的消息读回来（里面已经有上次那条），再推一条新的，然后整段存回去。**打开一次多一条。** 开发时热重载频繁，很快堆成一屏。平时不容易发现，因为一天也开不了几次。

**修法与一次走偏。** 第一版把过滤做在了界面层：显示和落盘之前先滤掉通知。表现上是好了，但我拿一个「老库」（`message` 表还没有类型列、且已被污染）独立探了一遍，发现读出来的通知会**原样返回**，再写回去就被盖上「对话」的类型——污染被洗白，以后再也认不出来。应用路径当时确实踩不到，可只要将来有人写一段「读出来、改一改、写回去」的代码（导出导入、迁移、分支复制），污染就会悄悄转正。

**最终形态。** 防线下沉到存储层，判据取最硬的那条：**`role === "system"` 一律不是对话**，写时拒收、读时滤掉，缺类型的历史行按 role 判而不是默认成对话。界面层那道过滤留着当双保险。`store-check` 补了 8 条断言把这三步固化：老库能迁移、读回来污染已滤掉、原样写回去也不会被洗白。

**教训。** 判断「这条信息该不该留下」，要问的是**它说的是团里发生了什么，还是程序刚才做了什么**。前者是这一场的记录，后者只是这一次打开时的说明。另外：一层的过滤只是修表现，把判据放到数据进出的那道口子上，才是修问题。

## 2026-08-18 · 主持人边写边出字接到画面上，用量面板补齐（T8）

**做了什么。** 流式草稿显示在叙述列末尾，灰色虚线、斜体、一枚「未定稿」徽章加一句「还没作数，可能被收回」；定稿到达才写进记录、才落盘。用量面板并排显示两份：按当前场面预估的下一份，和上一回合真正发给主持人的那一份。

**草稿进不了库是结构性的**，不是靠自觉：草稿存在 `narrationDraft` 这份独立状态里，`messages` 里从来没有它，而落盘只映射 `messages`。所以体检退回时，玩家看到的是守秘人改了口，记录里则干干净净。

**两份用量都是真实装配的结果**，没有按典型值折算——折算出来的数字会跟引擎脱节，那跟当初界面自己重跑 `route()` 是同一类错。

## 2026-08-18 · 界面上能换模组（T6）

**做了什么。** 顶栏的标题本身成了模组选择器，列出扫到的每一份；坏掉的那份也列出来，但不可选并写明原因——作者需要知道自己写的那份为什么用不了。换模组按「开新的一场」处理，旧的那场留在库里，换回去能接着玩。

**一个刻意选的笨办法。** 引擎从模块级单例读资料包，`state`、`narrate`、`resolve`、`router`、`runtime`、`session`、`keeper` 和若干界面都在导入时就拿到了它。要做成运行时切换，就得逐个确认没有一处缓存了派生值；漏掉任何一处都不会报错，只会在特定操作顺序下让玩家看见另一份模组的房间或开场白。所以改成：选择写进 localStorage，然后整页重载。重载前整页是旧包，重载后整页是新包，**中间态不存在**。状态本来就在 SQLite 里，重放即可续上。

**换回去能续上，靠的是已有机制。** `openCampaign` 本来就按 `packRef` 找最近一场，两份模组的引用不同，事件进不了同一条时间线。这一处没写新代码。

**教训。** 拿一个笨办法换掉一整类「不会报错的偶发错误」，几乎总是划算的。脚本环境没有 localStorage，所以冒烟不受影响——这也说明这条路子没有把行为绑死在浏览器上。

## 2026-08-18 · 主持人边写边出字（T7 引擎侧）

**难点从来不是流式，是它跟体检打架。** 规矩是叙述没过体检就整段作废、退回模板；可流式意味着半句话已经在屏幕上了。策略先定死：流式产生的文字在体检通过之前一律只是草稿，接口上草稿（`kind: "draft"` + `draft`）与定稿（`kind: "final"` + `text`）是两个字段，不许混着传。体检仍在整段收齐、过完契约校验之后执行，草稿从不进 `checkNarration`。

**结构化输出的碎片是个真问题。** 模型返回的是 `{"text": "..."}`，流式拿到的是这段 JSON 的碎片，把半截 JSON 吐给玩家不可接受。所以写了一个增量解析：还没进到字符串内容之前一律返回「暂无草稿」。我拿六段刁钻文本（含引号、换行、反斜杠、星平面字，以及正文里故意写 `"text":` 骗解析器的一段）逐字节切成 188 个前缀验过不变式——**抽出来的草稿始终是真文本的前缀**。真机流式 15 段草稿，首字 1 秒到，定稿与草稿一致。

**教训。** 「边出字」和「可以整段收回」是一对矛盾，解法不在代码技巧，在于**先承认草稿不是叙述**，再把这件事写进类型里。类型分开了，就没人会不小心把半句话存进记录。

## 2026-08-18 · 上下文用量面板（T5）

**做了什么。** `buildContext` 顺带返回分栏统计（每一栏的字数与被裁条数，空栏也占位），界面据此画出一扇观察窗：已用百分比、分段横条、九栏清单，被裁的地方写明「更早的经过已略去 N 条」。面板收在记录栏底部，默认折叠。

**这个面板最要紧的性质是「它没有第二条取数路径」。** 它只读 `buildContext` 的返回值，不碰 `GameState`、不查资料包、不读守秘人备注。所以「上下文里没有的东西，面板上也不会有」是结构上的，不是靠自觉。开锁前「看得见的东西」11 字，开锁后 16 字——账本是跟着上下文一起出现的。凡是这类展示秘密信息旁边的调试面板，都该按这个原则做：**只给已有数据称重，不新开取数口子。**

**验的是恒等式，不是眼睛。** 分栏统计必须与真发出去的文本对得上，否则面板就是摆设。除了它自己的断言，我另外拿五种场景独立验了「各栏之和 + 栏间换行数 = 文本长度」：空回合、500 条历史、预算 300、预算 20、40 条线索，全部成立，栏目数恒为 9，秘密零泄露。

**顺带纠正了依赖方向。** `session.ts` 原先从 `@/ui/` 引入 `PendingCheck`、`PendingAction`、`TurnMark` 三个类型，数据层反过来依赖界面。现在这三个都由 session 导出，`rg 'from "@/ui' src/session.ts` 一条都搜不到。

## 2026-08-18 · 界面不该自己猜引擎要做什么（T3）

**做了什么。** `session.ts` 现在公开两样它本来就知道的东西：一份 `pending`（路由之后、掷骰之前的意图与门槛，**类型里就没有点数、成功等级、成败**），和一份「已呈现的状态」。界面读后者，所以侧栏不会抢在守秘人开口之前变化。权威桌面收进 hook 内部的 ref，裁定之后照旧立刻提交、立刻落盘——这条底线没动。界面相应删掉了自己那套 `route()` 反推和快照冻结。

**关键在于「什么时候追上」。** 叙述落笔才追上（模型成功、退回模板、彻底失败都算，靠 `finally` 保证）；追问和查询不提交也不掷骰，立刻追上；回滚与切分支是权威和已呈现一起换成重放结果。这几种情况漏掉任何一种，界面都会莫名其妙地卡在旧值上，而且不会报错。

**为什么这样分层。** 上一轮界面为了不剧透，自己跑了一遍路由、又钉了快照。两处都能工作，但都是界面在替引擎兜底：路由一改，等待条就跟着说错话。现在「这句话算什么意图」只有一个出处。

**教训。** 界面为了正确显示而不得不重算引擎的东西时，缺的不是界面代码，是引擎没把话说全。

## 2026-08-18 · 上下文该有预算（T4）

**做了什么。** 叙述上下文有了字符预算（默认 4000，跟着主持人配置走）。超预算时按次序裁：先裁久远的公开经过，再裁较早的已知线索，**当前房间、在场的人、这一回合刚提交的事实一律不裁**——宁可超预算，也不能让模型在缺依据的情况下开口。裁掉的地方留「更早的经过已略去」这样的痕迹，否则模型会把节选当成全部，接着编。

**验的是底线，不是数字。** 预算这类改动最危险的地方不是裁多裁少，而是裁剪路径上出现一条没人想到的分支，把本不该出现的东西放了进去。所以除了它自己写的断言，我另外拿极端预算独立探了一遍：300 条历史，预算依次压到 4000、800、200、40，每一档都检查守秘人备注、未获得的秘密线索、藏着的道具名有没有出现。四档全是零泄露；预算压到 40 时上下文停在 172 字不再往下裁，核心栏目仍在——这正是设计要的行为。

**教训。** 「省空间」的代码天然倾向于把信息揉在一起，而信息一旦揉在一起，边界就容易破。给这类改动写测试，断言的应当是**什么绝不许出现**，而不是**结果有多长**。

## 2026-08-18 · 换一个模组不用改代码（T1）

**做了什么。** `pack.ts` 顶上写死的八行 `import` 换成了按目录扫描（Vite 的 `import.meta.glob`，Bun 跑脚本时走 `Bun.Glob`）。新增 `listPacks()` 与 `loadPackById()`；`pack` 与 `packIndex` 语义不变，所以引擎其余文件一行都没改。`pack:lint` 逐份体检。仓库里现在并排放着两份模组，第二份《雨夜照相馆》用来证明扫描是真的在扫描。

**一处关键的取舍：坏包不该连累别人。** 扫描阶段不再「加载即抛」——一份写坏的模组只让它自己不可用，程序仍能用好的那份开团。但**当前生效的那份坏了仍然是致命错误**，因为引擎不能带着半份资料跑。这两句话不矛盾：前者是编辑期的容错，后者是运行期的底线。

**返工了一处元编程。** 原先用 `Object.defineProperty(import.meta, "glob", …)` 在运行时给 `import.meta` 装属性。代价是实打实的：Vite 只静态替换 `import.meta.glob(...)` 这个调用点，不替换 `typeof` 判断，于是浏览器每次加载都要跑一遍只有 Bun 才需要的回退，整段回退还被打进了浏览器包。改成一句普通的三元（`typeof Bun !== "undefined" ? 扫描 : glob`）之后，两条路各自短路，逻辑等价而少一层魔法。已验证 Vite 在开发态与构建态都仍会静态展开三元里的那个 glob。

**顺手把「靠人看」变成「自动证明」。** 体检新增一条：凡是写了 `lockedBy` 或 `hidden` 的道具，`itemVisibility()` 都不许判成 always；并指名断言《雨夜照相馆》那张未干的相片在锁没开时算看不见。将来有人加第三份模组又把可见性写反，体检当场就喊。

**教训。** 载入这类地基代码，宁可多写三行普通分支，也不要少写一行元编程。前者接手的人一眼看懂，后者要靠读打包器的行为才敢下结论。

## 2026-08-18 · 跑团桌打磨（T2）

**做了什么。** 等待条改成只报门槛不报成败；检定尺可以展开自证门槛怎么算；窄屏三栏收进底栏；守秘人、调查员、系统三类消息分开；时间线能看出哪回合掷了骰、哪回合分了叉。

**过程中发现的第二个泄底出口。** 提交发生在叙述之前，所以理智、背包、建议行动会抢在守秘人开口之前变化——玩家不用读叙述就知道成没成。眼下的处置是界面在忙碌期间钉住提交前的桌面快照。这是权宜之计，记在欠账里了：正解是 `session.ts` 公开一份「已呈现的状态」，让它落后于权威状态，直到叙述落笔。

**返工了一处。** 界面自己把「困难看一半、极难看五分之一、技能值不到 50 时大失败从 96 起」又算了一遍。当时两处结果一致，但房规阈值迟早要做成可切换的，到那天引擎改了、界面还按老规矩画门槛，玩家看到的数字就是错的，而且不会有任何报错。现在门槛只在 `engine/rules.ts` 的 `skillBands` 与 `thresholdFor` 里算，裁定与界面共用一份。提取之后拿改动前的原式逐格比对过 30000 种技能值与点数的组合，判定完全一致。

**教训。** 规则的数学只能有一个出处。界面里出现除法或者 96、100 这样的字面量，就是它开始自己解释规则的信号。

## 2026-08-18 · 补上数据泄底的口子

**病症。** 玩家的建议行动里出现了「看看黑色账本」，而账本本该锁在写字台里；模型还顺势编出「你拿起账本翻开」这种没发生过的动作。

**根因。** `lockedBy` 当时只挡住了「拿不走」，没挡住「看得见」。于是账本的名字照样进了房间描述、建议行动、界面清单和模型上下文——四个出口一起漏。这不是提示词的问题，是数据模型少了一个维度。

**处置。**

- 可见性升级成资料包的字段：`hidden`、`revealedWhen`、`lockedBy`，判定口径收在 `itemVisibility` 一处，写进 `SPEC.md`。
- 路由不再拿「在不在场」当「听不懂」：玩家叫得出名字就认得出来，在不在场交给裁定回答，回答与「不存在的东西」完全一致，试探问不出秘密。
- 叙述体检新增一类：模型替玩家把没做过的动作做完（拿起、翻开、开锁、换房间），一律退回重写。
- 体检新增四条可见性查错，并且给体检本身加了自检——这道关口坏掉不会报错，只会安静放行。

**教训。** 凡是「玩家能不能知道」的事，必须是数据里的一个显式字段，并且只有一处判定。散在各处的判断迟早有一处忘记加，而漏出去的那一次没有任何报错。
