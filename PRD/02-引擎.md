# 需求：引擎

状态：草稿  
来源：上游 `docs/01-architecture`、`docs/02-data`、`docs/03-ai`；V1 落地规格见 [`docs/05-implementation-design/`](../docs/05-implementation-design/README.md)

下面列出的都是逻辑职责，不是一个个独立的进程。可运行的参考实现在 `demo/`。桌面 `src/` 仍是聊天外壳。V1 Draft 要求权威提交发生在主进程，渲染进程只走 IPC。

## 1. 不可逾越的边界

```
理解意图 →（若有必要）按规则裁定 + 掷骰 → 校验 → 原子提交 → 叙述
```

重试叙述时沿用同一个 `turn_id` 和 `state_version`，不得重新掷骰、重复消耗资源，也不得再提交一次。

叙述与已提交的状态打架时，保住状态，改叙述，或者报异常。

## 2. 分层

| 层 | 组件 | 能写事实吗 |
| --- | --- | --- |
| 客户端 | 跑团桌界面 | 不能 |
| 台前 AI | 主持人（本演示中是守秘人） | 不能，只能输出澄清、意图、叙述和上下文请求 |
| 幕后 AI | 导演、记忆、临时上下文管理、领域分析 | 不能，只能给出带出处的候选 |
| 运行时 | 协调器、回合路由、规则引擎、掷骰服务、剧本运行时、校验、可见性、事件、状态库 | 能，但要先过校验 |
| 模型接入 | 网关、能力登记、结构化输出、重试、自带密钥 | 不能 |
| 权威数据 | 实体状态、事件记录、裁定记录、分支元数据 | 它本身就是权威 |
| 派生数据 | 领域视图、关系索引、检索、临时上下文库 | 可以随时重建，永远不算权威 |

不设单独的「剧情 AI」：路线上的建议归导演，世界层面的后果归世界领域，历史因果归记忆，节点的正式状态归剧本运行时。

导演不是第二位主持人，也不直接对玩家说话。

## 3. 回合路由

| 级别 | 什么时候走这一档 | 同步的模型调用 |
| --- | --- | --- |
| 0 纯扮演 | 交谈、表态，既不检定也不改动权威状态 | 主持人调用 1 次 |
| 1 建议行动 | 玩家点了一条带结构的建议 | 先由程序裁定，再主持人调用 1 次 |
| 2 简单自由行动 | 动作和目标都唯一，能够保守匹配上 | 先由程序裁定，再主持人调用 1 次 |
| 3 复杂自由行动 | 动作复合、含糊，或者重大风险没有说清楚 | 主持人走一轮工具闭环，然后程序裁定，最后叙述 |
| 澄清 | 缺了某个会改变结果的选择 | 主持人调用 1 次；既不掷骰也不提交 |

快路径宁可漏判，也不能错判：严禁靠宽松的关键词匹配就直接执行。

导演和记忆**不是**每个回合都要交的税。程序先检查确定性触发条件（进出房间、关键线索的得失、节点条件翻转、长时间没有推进），命中了才调用导演。记忆则在场景结束、攒够 N 个回合、存档或者空闲的时候批量整理。

## 4. 主持人的输出类型

一次模型输出只允许属于一种类型。

| 类型 | 可以包含 | 禁止包含 |
| --- | --- | --- |
| `clarification` | 需要玩家确认的问题，以及可选的结构化选项 | 掷骰、提交 |
| `context_request` | 请求理由、实体编号、允许访问的视图 | 完整的模组答案、其他 NPC 的秘密 |
| `action_intent` | 行动者、目标，以及玩家已经说出口的方式与风险 | 成败、技能、难度、点数、生命值、节点推进 |
| `narration` | `turn_id`、`state_version`、叙述正文、建议行动 | 该版本状态里并不存在的事实 |

建议行动必须同时具备两样东西：给玩家看的文案，以及回合路由用得上的结构化字段。

主持人不得张口就说「你掷出 3，锁开了」。检定的点数只能来自程序。

## 5. 导演

导演只回答一个问题：已经发生的这些事实，让哪些剧情路径依然成立、哪些受阻、哪些彻底失效？

它可以提出失败推进的方案，可以给出替代的线索、NPC 或地点，也可以提出适应性节点。适应性内容必须打上标记，不能冒充模组原文。

它不可以：

- 改写剧本正文（Scenario Canon）或者已经提交的历史
- 撤销玩家造成的失败
- 白送关键线索给玩家
- 强行保证原定的结局
- 自己去写 `StoryProgress`

输出是 `director_proposal`：触发事件、受影响的节点、判断、带出处的方案，以及过滤之后交给主持人的引导。

## 6. 权威

**状态库**是某个分支上当前已提交的全部事实，外加一个 `state_version`。  
**事件记录**说明这些事实是怎么来的：一旦提交就不能原地修改、不能删除，只能往后追加。

一次变更请求要带上：目标、期望的前一个版本、候选的新值、来源事件、依据的规则、对可见性的影响。校验过模式、不变量、引用、权限和跨领域一致性之后，一次性原子提交，版本号加一。

跨领域的半提交是非法的。派生视图可以落后一点，但不能假装自己是最新的事实。

聊天记录、战报和主持人的叙述，都不是权威。

### 事件的最低字段

`event_id`、事件类型、`branch_id`、顺序号、`turn_id`、提交后的 `state_version`、团内时间、来源主体、原因引用、受影响的实体、公开范围。领域相关的载荷属于附加信息，不能拿来顶替上面这些可追溯字段。

玩家的输入、AI 给出的候选、被拒绝的写入，都记进诊断日志，不算正式的领域事件。

牵涉规则的事件必须引用：规则资料包的版本、输入状态、修正值的来源、随机种子、骰式（xDy）以及掷出的结果。

### 存档、读档、回滚、分支

存档不是聊天记录的副本，也不与当时用的那只模型绑定。

检查点记录的是：战役（或者可以续场的团）、分支、事件游标、状态版本、状态哈希，以及模组和规则资料包的引用。快照只是缓存。恢复的办法是：取一份可信的快照，再重放其后的事件；哈希对不上就退回更早的检查点。任何情况下都不许用叙述来补状态。

回滚不会删掉「未来」：它在选定的检查点上新建或激活一个分支，旧分支依然可以查看。

更正只有两种做法：写一条更正事件，或者开一个新分支。玩家掷骰不佳不属于系统错误，不能拿静默更正把它撤销掉。

## 7. 实体

- 用稳定的 `entity_id`，显示名不能当键。
- 分清三样东西：**定义**（来自资料包）、**实体状态**（团内的）、**派生视图**（供查询）。
- 一条事实只归属一个领域，其他领域只保存引用。
- 创建、死亡、销毁、离场都要写成显式事件，不许靠删行来抹掉历史。
- 可见性按字段、按听众分别控制。

本演示涉及的实体有：调查员、NPC、房间、出口、道具实例、线索、剧情标记、开关／变量、条件。

## 8. 上下文

分四层：权威数据 → 投影 → 临时上下文库（可以重建的工作集）→ 单次任务的提示词快照。

每份提示词都要绑定 `task_id`、`turn_id`、`branch_id`、`state_version`、听众、提示词版本、来源清单和预算。

主持人看到的是：玩家可见的事实，加上过滤之后的「可以怎么演／禁止透露什么」。导演能看到更多剧本正文。针对某个 NPC 的任务，只能看到这个 NPC 自己知道的事。绝不能把一名职责的完整上下文原样喂给另一名职责。

最近的原始对话只保留很短的一个窗口，更早的团内经历通过事件记录和可追溯的记忆进入上下文。

## 9. 模型策略

职责不等于供应商。多个职责可以共用一只模型；同一个职责也可以按意图、叙述、后台整理这些场景分别换档。

网关统一处理消息、工具、结构化输出、超时、重试和用量统计，业务侧只认任务契约。

用户自带的密钥不得进入提示词、事件记录、存档，也不得进入默认的诊断信息。

回退方案同样要满足结构和隐私要求：结构化任务不能回退到守不住模式的模型，涉密任务不能离开允许的位置。

模型的输出一律当作不可信的候选。

## 10. 失败处理

| 失败情形 | 应有的行为 |
| --- | --- |
| 校验或提交失败 | 不叙述结果，保留待处理的回合，允许安全重试 |
| 提交之后主持人失败 | 按同一次提交重新生成叙述 |
| 快路径吃不准 | 降到 3 级，或者转为澄清 |
| 导演／记忆失败 | 进队列排队；除非当前行动直接依赖它，否则不阻塞普通回合 |
| 叙述与状态冲突 | 保住状态 |
| 同一个 `turn_id` 重复提交 | 只有一次能成功 |

回合阶段的完整名单、`CommandEnvelope`、`Candidate`、`correction.applied` 见 [10-application-runtime](../docs/05-implementation-design/10-application-runtime.md) 与 [04-event-state](../docs/05-implementation-design/04-event-state.md)。V1 事件用过去式领域名（`item.transferred`、`character.moved`）；Demo 仍用切片名（`lock_opened`、`npc_moved`），搬迁时对照，不要两套并行当权威。

掷骰算法 V1 锁 `xoshiro256ss-v1`，决策种子走 HMAC-SHA256（`branchId+turnId+decisionId`）。Demo 现在是 mulberry32。金样要换算法时必须重算哈希，不能 silently 改。

## 11. 引擎验收

- 同样的状态、输入、规则资料包和种子，必须得出同样的程序裁定。
- 主持人写不进点数、难度和数据行。
- 纯扮演、建议行动、简单自由行动这三档，都只调用一次主持人，不额外开一个解析模型。
- 记忆和导演不按固定回合数收税。
- 只有聊天记录的文件读不出档。
- 重放《寄宿公寓账本》的事件栈，得到的数据卡与状态必须一致。
