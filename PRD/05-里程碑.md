# 里程碑

来源：上游 AI TRPG Engine `docs/00-product/roadmap.md`  
不承诺具体日期。一个阶段只有把退出条件全部满足，才算结束。

每个阶段都必须是一块**纵向**的可玩切片，几个互不相干的模块堆在一起不算数。

## 总览

```
原型      →  试玩 Demo  →  V0.1     →  V0.x   →  V1.0        →  更远
机制成立     一晚的体验     可以分发    做加固    兑现单人承诺     多人／真人主持人
```

**现在：** `demo/` 已经把 M0／M1 的游戏语义做完（事件、重放、主持人写不了事实、寄宿公寓桌）。`electron/` 是 V1 外壳：主进程管库，渲染进程只走 `desktopApi`。`src/` + `src-tauri/` 是旧 Tauri 聊天壳，不再跟。

对照 V1，还没到可分发：回合提交仍在 Renderer／Demo 里，`turn:submitAction` 尚未进主进程。

## M0 — 原型（对内）

**目标：** 证明核心链路走得通。命令行或者难看的界面都行，输入固定，配一份测试用的规则资料包和一个最小模组。

### 必须验证

- 玩家输入 → 路由 →（规则裁定）→ 校验 → 提交 → 主持人根据已提交的状态叙述
- 主持人编不出点数，也覆盖不了事实
- 固定种子的前提下，事件能重建出状态
- 临时上下文足够喂给下一个回合，不必把整个库倒出来
- 哪些职责非上模型不可，哪些用普通程序就够了（写成实验记录）
- 延迟、用量和失败形态都还在可以继续做下去的范围内

### 退出条件

- [x] 一个回合能完整走通：理解 → 裁定 → 提交 → 叙述 → 下一回合（`demo/`）
- [x] 状态与主持人的叙述之间没有无法解释的冲突（叙述体检）
- [x] 固定输入加固定种子，得到同样的裁定和同样的结构化状态（哈希 `b6506aeb`）
- [x] 失败是看得见的，不存在静默的半提交
- [ ] 有一份实验记录，写明哪些架构假设成立、哪些作废
- [x] 同一条链路改由 Electron 主进程提交（W0）

### 这一阶段不做

完整的跑团桌、人设卡导入、长期战役、作者工具、多人。

**本仓库的切片：** 只做寄宿公寓里的锁和账本，用无界面测试加现有的聚会页面就够了。

## M1 — 试玩（一晚上能跑完）

**目标：** 拿出一份精细适配的一次性模组，体验上不像「聊天窗口加人设卡」。

### 玩家能得到

- 以叙述为中心的跑团桌，而不是一个裸的聊天框
- 建议行动，并且随时可以自由输入
- 由主持人扮演的 NPC
- 人物卡、道具、房间、线索、剧情标记
- 公开检定
- 一个有开场、有发展、有结局的短剧本
- 基础的存档、读档和回合记录

### 退出条件

- [ ] 玩家从选用林晚开始，不用开发者在旁边就能跑完这个短剧本
- [ ] 至少有一次不在建议列表上的自由行动被合理承接
- [ ] 关键人物、道具、房间和剧情标记，都没有无出处的变化
- [ ] 存档之后能回到可以续场的状态
- [ ] 试玩的人说得出它和普通对话框的区别

### 这一阶段不做

任意人设卡、完整规则书、几百个回合的长团、模组制作软件。

**本仓库的切片：** 《寄宿公寓账本》，详见 `handbook/` 与 [03-内容与规则.md](03-内容与规则.md)。

## M2 — V0.1（第一份可分发的版本）

**目标：** 外面的人能装上、接好模型、导入资料、自己开团、正常存档。

### 玩家能得到

- 一个可以安装的 Electron 包（V1.0 目标平台 Windows x64）
- 创建、继续和管理单人战役（或者可以续场的团）
- 主持人依然是唯一的台前
- 模型、密钥和本地地址的设置界面
- 普通人设卡的导入（人设、开场白、示例对白、世界书）
- 能力标记：人设卡／轻量冒险／完整模组
- 一种正式的模组资料包格式，外加寄宿公寓这个示例
- 一份百分规则资料包
- 结构化的权威状态、事件记录和基础的长期记忆
- 存档、读档、失败重试和基础的恢复能力
- 对普通人说得明白的兼容性说明、模型能力说明和错误提示

### 人设卡的边界

- 台前依然只有一位主持人，不给人设角色另开一条绕过主持人的聊天线程。
- 只有人设卡的时候，不虚假承诺完整规则和精确的房间状态。
- AI 补写的内容一律标成候选。
- 用户确认过结构之后，同一份资料可以升级为轻量冒险或者完整模组。

### 退出条件

- [ ] 外部用户能独立完成安装、配置，并开出第一团
- [ ] 常见的人设卡能被解析，并且在主持人手里表现连贯
- [ ] 用户分得清人设卡和模组的区别
- [ ] 创建 → 游玩 → 存档 → 退出 → 续场，整条路走得通
- [ ] 至少有一份正式模组能从开场跑到结局
- [ ] 缺失的结构不会被悄悄装扮成作者的设定
- [ ] 状态变化和裁定都能追溯到来源
- [ ] 常见的模型失败不会破坏已经提交的状态

### 这一阶段不做

覆盖所有人设卡变体、可视化编辑器、上百回合的稳定性保证、多人。

## M3 — V0.x（加固单人跑团）

具体顺序要看 V0.1 上线后的使用情况和失败情况，不提前把小版本号写死。工作主要集中在这几块：

1. **长期战役** —— 临时上下文、检索、淘汰、重放、回滚、分支、哈希和成本
2. **资料生态** —— 更多人设卡与世界书，人设卡→轻量冒险→完整模组的升级路径，校验、试玩、迁移，以及作者文档
3. **规则能力** —— 更强的规则资料包、检定解释、房规、歧义确认；等边界足够干净了再考虑接入第二套规则
4. **模型适配** —— 用实测数据做能力登记、切换和降级，支持更多本地与云端模型
5. **跑团桌** —— 叙述、NPC 呈现、检定、人物卡、首次配置和故障处理

某个主题在有自己的退出清单之前，不单独开一个里程碑编号。

---

## M4 — V1.0（兑现单人承诺）

由 AI 主持的单人跑团，成为一个稳定的产品；这不等于「把所有远期想法都做完」。

- 普通玩家能独立安装、配置、导入资料、开团、存档并跑完
- 跑团桌、自由行动、规则裁定、状态反馈都稳定一致
- 人设卡和轻量资料对自己的能力足够诚实
- 作者能制作、检查、试玩并发布正式的模组资料包
- 在声明的战役长度内，关键事实和因果关系站得住
- 裁定和掷骰可以审计
- 模型可以随时替换，它不是存档里的事实
- 存档、回滚和分支齐全，出错时不会悄悄改写历史
- 面向玩家、作者、模型配置和故障排查的说明都完整

### 依然不承诺

多人实时团、真人主持人工作台、支持一切规则书／人设卡／模型供应商、大批自主 NPC 组成的社会。

---

## 更远的事（现在不建）

1. 在 AI 主持之下，多名玩家同桌
2. 真人主持人加入，与 AI 分担主持、准备、扮演、记录和规则
3. 一套完整的真人主持人工作台

模式上不要把路封死（分支、听众、职责都保留），但在真正进入对应阶段之前，不实现同步机制和主持人权限系统。
