# 技术选型

状态：**已锁定**。外壳走 Electron，权威规格以 [`docs/05-implementation-design/`](../docs/05-implementation-design/README.md) 为准。  
原则：继续在本仓库上做，不另起一套程序。

## 1. 决定

| 需求 | 选型 | 理由 |
| --- | --- | --- |
| 外壳 | Electron（Main + Preload + 单一 Renderer） | V1 模块设计锁的进程与安全边界。代码在 `electron/`。 |
| 跨进程 | 类型化 `window.desktopApi`，channel 为 `<namespace>:<verb>` | 渲染进程不可信，不暴露通用 `invoke`，不碰 SQLite。 |
| 权威库 | 主进程 `better-sqlite3`：`settings.sqlite` + 每场 `campaign.sqlite` | 与 [03-persistence](../docs/05-implementation-design/03-persistence.md) DDL 一致。 |
| 界面 | React 19 + Vite 7（现阶段复用 `demo/` 跑团桌） | 内核已经可玩；桌面窗口只是把它装进 Renderer。 |
| 模式定义 | Zod 4 | IPC 请求 `.strict()`，主持人契约同一套。 |
| 密钥 | Electron `safeStorage`（Windows 上是 DPAPI） | 密钥不进 SQLite、不进 Renderer、不进日志。 |
| 语言 | 引擎与主进程服务用 TypeScript | 领域模块不依赖 Electron、React 或供应商 SDK。 |
| 包管理 | Bun | 当前工作区用的就是它。 |
| 作者文档 | Astro 手册工作区 | 试玩模组的人读权威。 |

`src-tauri/` 与 `src/lib/db.ts` 直连插件 SQL，是旧聊天外壳，**不再跟、不再加功能**。浏览器里的 `demo/` 仍可单独开，用来快速试玩；正式权威提交的目标落点是主进程。

## 2. 现在不加的东西

- 把主持人、导演、记忆拆成多个进程
- Postgres、Redis、图数据库
- 向量库（先用 FTS5 加结构化过滤）
- Next.js 或者多租户的托管接口
- Python 系的多智能体框架
- 官方 5e 或者《克苏鲁的呼唤》的授权文本
- 继续往 Tauri / 渲染进程 SQL 上堆功能

## 3. 目标模块结构

```
electron/
  main/           生命周期、组合根、IPC 注册（这里不许写 SQL 或规则）
  main/persist/   better-sqlite3、migration、仓储
  main/services/  战役等应用服务
  preload/        白名单桥，只暴露 desktopApi
  shared/         DesktopApi、Result、品牌 ID
  sql/            settings.sql / campaign.sql（V1 DDL）
demo/src/engine/  回合内核参考实现，下一步搬进 main/services
demo/src/ui/      跑团桌 Renderer
```

`src/lib/tools.ts` 里会写库的工具对 V1 非法，桌面路径不得再走它们。

## 4. SQLite 布局

以 [V1 Persistence](../docs/05-implementation-design/03-persistence.md) 为准。`electron/sql/` 已按原文落地：

- `settings.sqlite`：`campaign_catalog`、`app_settings`、`provider_instances`、`model_profiles`、`task_routes`、`installed_content`
- `campaign.sqlite`：`branches`、`turns`、`operations`、`events`、`state_entities`、`rule_decisions`、`narrations`、`snapshots`、`checkpoints`、`content_bindings`、`background_jobs`

`events` 的 UPDATE／DELETE 由触发器拒绝。对话记录不是权威，不进战役库。

Demo 浏览器库仍是子集，只服务无壳试玩。

## 5. 模型的输入输出

- 任务名对齐 V1：`gm.interpret_action`、`gm.narrate_result`。
- 工具只读或只提议。写入只发生在主进程 `TurnApplicationService` 提交里。
- 本地默认 Ollama；云端自带密钥，经 `safeStorage`。

## 6. 测试

| 层 | 工具 |
| --- | --- |
| 规则、掷骰、提交、重放 | `cd demo && bun run smoke` |
| 资料包校验 | `cd demo && bun run pack:lint` |
| 主进程 DDL／迁移／不可变事件 | `cd electron && bun run persist:check` |
| 手册 | CI 里跑一次 Astro 构建 |

金样：固定种子跑《寄宿公寓账本》，事件记录和状态哈希必须一致（当前 `b6506aeb`）。

## 7. 分发

- V1.0 正式目标：Windows x64。开发机可以用 macOS 跑 Electron。
- 不做账号服务器。遥测不保存密钥，也不保存完整提示词。

## 8. 明确不选的方案

| 方案 | 现在不选的原因 |
| --- | --- |
| Tauri 继续当外壳 | 与 V1 的 Main／Preload／`DesktopApi`／`better-sqlite3` 边界冲突 |
| 渲染进程直连 SQLite | 违反 IPC 安全边界 |
| 把引擎整段改写成 Rust | 挡住搬迁；领域逻辑留在 TypeScript 主进程 |
| 托管版主持人 | 破坏本地优先 |
| LangGraph 这类多智能体操作系统 | 与「一位主持人、由程序提交」冲突 |
