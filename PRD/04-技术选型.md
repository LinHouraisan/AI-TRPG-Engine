# 技术选型

状态：已经为 AI TRPG Engine 锁定  
原则：继续在本仓库上做，不另起一套程序。

上游文档不锁定任何供应商。本文件锁的只是**这一份实现**，目的是把试玩和 V0.1 做出来。

## 1. 决定

现在的形态是对的：本地桌面程序、自带密钥或者本地模型、SQLite、带类型的工具调用、中文手册。引擎需求里说的那些「服务」都是逻辑职责，落地成同一个进程里的 TypeScript 模块，不是微服务。

| 需求 | 选型 | 理由 |
| --- | --- | --- |
| 外壳 | Tauri 2 + Rust | 能访问本地文件、SQLite、系统钥匙串和模型接口，安装包还小。 |
| 界面 | React 19 + Vite 7 | 现有的跑团桌就是这一套，改起来快。 |
| 路由 | TanStack Router | 文件路由已经在用了。 |
| 服务端状态 | TanStack Query | 提交之后作废缓存很方便。 |
| 界面局部状态 | Zustand | 侧栏、上一次玩的战役这类。 |
| 组件 | Base UI + shadcn + Tailwind 4 | 已经在依赖树里了。 |
| 模型调用 | Vercel AI SDK 7（`ai`） | 支持流式、工具和结构化输出，不绑死在一家供应商上。 |
| 供应商 | `@ai-sdk/openai-compatible`、OpenAI、Anthropic | Ollama、LM Studio、OpenRouter 和自定义端点都已经有映射。 |
| 模式定义 | Zod 4 | 用于工具参数，以及主持人和导演的契约。 |
| 权威库 | SQLite（`@tauri-apps/plugin-sql`） | 一场战役一个文件，并且支持事务。 |
| 密钥 | `keyring`（Cargo 里已有） | 密钥不进 SQLite，也不进提示词。 |
| 作者文档 | Astro 手册工作区 | 试玩模组的人读权威。 |
| 语言 | 引擎用 TypeScript；Rust 只管外壳、钥匙串和日后的热点 | 先把试玩跑通，不重写主循环。 |
| 包管理 | Bun | 当前工作区用的就是它。 |

## 2. 现在不加的东西

- 把主持人、导演、记忆拆成多个进程
- Postgres、Redis、图数据库
- 向量库（先用 FTS5 加结构化过滤）
- Next.js 或者多租户的托管接口
- Python 系的多智能体框架
- 官方 5e 或者《克苏鲁的呼唤》的授权文本

如果到了 V0.x，长战役的检索确实被 FTS5 加事件扛不住了，再把嵌入向量当成**派生索引**引进来，但它永远不能当事实源。

## 3. 目标模块结构

```
src/
  engine/
    runtime/          协调器、回合路由、回合状态机
    rules/            加载规则资料包、检定、效果
    rng/              带种子的掷骰，与 turn_id 绑定
    scenario/         节点与剧情进度
    validate/         模式、不变量、版本
    visibility/       按听众切分的视图
    events/           只追加的事件记录与重放
    state/            当前实体、房间、道具、剧情标记
    save/             检查点、哈希、分支
    context/          上下文调度 + 临时上下文库（程序侧）
    ai/
      gateway.ts      模型进出、重试、用量
      gm.ts           主持人的提示词与输出联合类型
      director.ts     触发之后的导演提案
      memory.ts       批量生成的记忆候选
      contracts.ts    Zod 输出类型
  data/packs/         规则与模组的 JSON
  components/desk/    叙述、建议行动、检定明细、人物卡
handbook/             作者手册（保留）
```

现有的 `src/lib/tools.ts`、`check.ts`、`db.ts`、`prompt.ts` 要**迁进** `engine/`，不要继续往聊天外壳上堆功能。

## 4. SQLite 布局

权威部分：

- `campaign`（战役）、`branch`、`checkpoint`
- 按 `branch_id` 加 `state_version` 组织的规范化表（三个房间的规模优先用表，不要整包 blob）
- `event`（不可修改）
- `rule_decision`（检定与裁定）
- `turn`（阶段、输入、幂等键）

派生部分（丢了也无所谓）：

- `projection_*`
- `active_context`
- `memory_summary`（必须引用事件编号）

永远不算权威的部分：

- `message`（对话）。它只是为了让叙述读起来连贯，读档绝不能依赖它。

## 5. 模型的输入输出

- 主持人的结构化输出走 `generateObject` 或 `Output`，配合 Zod 联合类型。
- 工具要么只**读**（上下文调度），要么只**提议**（意图）。真正的写入统一走 `Runtime.commit`。
- 过了原型期，现有那些会写库的工具（`update_character`、战斗相关的变更）对主持人就是非法的，改由路由去调用领域函数。

本地默认用 Ollama 的 OpenAI 兼容接口，云端默认让用户自带密钥。能力登记先做一张静态表（上下文长度、是否支持工具、是否支持 JSON、本地还是云端）。

## 6. 测试

| 层 | 工具 |
| --- | --- |
| 规则、掷骰、提交、重放 | `bun test`（或 Vitest），纯 TypeScript |
| 资料包校验 | `bun run pack:lint` |
| 跑团桌 | 先靠手玩，日后再补组件测试 |
| 手册 | 在 CI 里跑一次 Astro 构建 |

金样测试：固定种子，配上脚本化的《寄宿公寓账本》输入，跑出来的事件记录和状态哈希必须完全一致。

## 7. 分发（V0.1）

- 先用 `tauri build` 出 macOS 版本，试玩过关之后再谈 Windows 和 Linux。
- 不做账号服务器。默认的遥测不保存密钥，也不保存完整提示词。

## 8. 明确不选的方案

| 方案 | 现在不选的原因 |
| --- | --- |
| Electron | 比 Tauri 重，而且 Tauri 已经在用了。 |
| 把引擎整段改写成 Rust | 等重放真的慢到不能忍再说，现在做会挡住试玩。 |
| 托管版主持人 | 破坏「本地优先」和「自带密钥」两条前提。 |
| LangGraph 这类多智能体操作系统 | 与「只有一位主持人在台前」「由程序提交」这两条原则冲突。 |
