# Director / 幕后剧本 AI

## 定位

Director 是幕后的剧本分析与路径适应 AI。它根据已提交事件、当前 `StoryProgress`、Scenario Canon 和相关领域视图，判断玩家行为对剧本可行性的影响，并提出带来源的适应方案。

Director 主要回答：

> 已经发生的事实使哪些剧情路径成立、受阻或失效？在不撤销玩家选择、不违反剧本核心设定的前提下，接下来还有哪些合理路径？

Director 不是世界状态的所有者，也不是剧情节点的执行者。正式节点变化必须由 Scenario Runtime 验证并提交。

## 调用时机

Director 不在每个回合同步调用。Runtime 首先检查确定性触发条件，只在需要语义或因果分析的重要变化发生时调用，例如：

- 获得、失去或破坏关键线索；
- 关键 NPC 死亡、失踪、背叛或改变阵营；
- 关键地点无法进入或被永久改变；
- ScenarioNode 的前置、完成或失败条件发生变化；
- 原定剧情路径失效或玩家进入未预设路线；
- 玩家长时间没有获得有效推进；
- 场景结束，需要评估后续可用节点。

普通对话、常规观察和没有改变剧情条件的行动不会触发 Director。

## 职责

Director 负责：

- 分析已提交事件对剧情结构的影响；
- 判断原有剧情路径是否仍然可行；
- 识别失效、受阻或不可达的节点与线索；
- 在原路径失效时提出替代 NPC、地点、线索或事件；
- 为玩家偏离预设路线后的剧情适应提出候选；
- 发现剧情停滞、线索断裂和伏笔回收机会；
- 提出符合当前因果链的 fail-forward 机会；
- 向 Runtime 提供带来源的剧情候选；
- 提供经过过滤后可交给 GM 的叙事方向与引导建议。

Director 可以分析领域事件对剧本的影响，但不代替领域模块决定状态变化：

- NPC Domain 决定 NPC 的状态、知识、关系和计划；
- Item Domain 决定道具的位置、数量和状态；
- Scene Domain 决定场景的增量变化；
- World Domain 决定时间、地点和全局影响；
- Director 只判断这些事实对剧情路径意味着什么。

## 可读取的信息

Director 可以读取比 GM 更完整的剧本信息，但仍遵循完成当前分析所需的最小范围，包括：

- Scenario Canon 和 ScenarioNode 定义；
- 当前 `StoryProgress`；
- 已提交的相关事件；
- 关键 NPC、道具、场景和世界状态；
- 线索关系、预设结局条件和已有替代路径；
- 相关长期记忆及其来源事件。

Director 不能将原始秘密分析直接传给 GM。Runtime 和 Visibility Policy 必须先将其转换为当前可用的叙事方向、行动机会、伏笔和禁止透露事项。

## Scenario Canon 与可变范围

Scenario Canon 是 Director 不能直接修改的剧本基础，包括：

- 世界和剧本的核心设定；
- ScenarioNode 原始定义；
- 关键事实和结局条件；
- 重要实体的初始身份；
- 剧本声明的硬性因果约束；
- 玩家已经经历并提交的历史事实。

原始 `ScenarioDefinition` 保持不可变。以下进度可以变化，但必须由 Scenario Runtime 提交：

- 节点锁定、可用、完成、失败或被替代；
- 原定路径是否仍然可行；
- 哪个替代线索、NPC 或地点已经生效；
- 当前采用的支线、结局方向或适应性节点。

所有适应性变化都必须保留触发事件、来源实体和采用原因。

## 创建新剧情的边界

Director 可以提出原剧本未明确写出的适应性剧情候选，但候选必须：

- 不与 Scenario Canon 和已提交历史冲突；
- 不撤销玩家造成的不可逆结果；
- 能从现有实体、事件或世界状态中建立因果来源；
- 不让角色使用其不知道的信息；
- 不让关键实体无原因出现、消失或移动；
- 不直接完成条件尚未满足的关键节点；
- 经过相关领域约束和 Scenario Runtime 校验；
- 被标记为适应性内容，而不是伪装成原始剧本内容。

## 玩家偏离剧本

玩家偏离原路线时，Director 不应强行将玩家拉回。处理顺序为：

1. 判断原剧情是否仍与玩家当前目标相关；
2. 检查是否存在仍然成立的原始节点；
3. 寻找能从当前状态自然连接的替代路径；
4. 必要时提出适应性节点；
5. 玩家明确放弃目标时，允许剧情线失败、休眠或转为后台后果；
6. 所有合理路径失效时，允许进入替代结局或自然结束。

关键节点固定的是必要事实、核心冲突或结局条件，不是玩家必须经过的固定场景。

## Fail-forward 边界

Fail-forward 表示失败保持为失败，但可以产生新的局面、代价或行动机会。

Director 可以建议失败引发冲突、关闭原路线、开放代价更高的替代路线，或者使时间、资源、关系和位置发生有来源的后果。

Director 不能：

- 把失败改写成成功；
- 免费返还已经失去的资源；
- 撤销死亡或其他不可逆结果；
- 自动把关键线索交给玩家；
- 在前置条件不满足时完成剧情节点；
- 为保证剧情继续而制造无来源的巧合；
- 保证玩家一定抵达原定结局。

Fail-forward 保证失败后仍可能存在有意义的游戏，而不是保证原剧本必然完成。

## 输出契约

Director 输出 `director_proposal`，至少包含：

- `trigger_event_ids`：触发分析的已提交事件；
- `affected_node_ids`：受影响的剧情节点；
- `assessment`：路径成立、受阻或失效的判断与原因；
- `proposals`：带来源实体和必要条件的适应方案；
- `gm_guidance`：允许交给 GM 的叙事机会和禁止透露事项。

输出必须区分分析结论、状态变化候选和 GM 建议，不能包含直接数据库写入指令。GM 建议在经过 Visibility Policy 过滤前不得进入 GM 上下文。

## 禁止职责

Director 不负责：

- 直接修改权威状态或 `StoryProgress`；
- 决定规则或随机结果；
- 决定领域模块的最终状态；
- 替代 Memory AI 保存长期记忆；
- 替代 GM 生成最终玩家叙事；
- 强迫玩家执行指定行动；
- 重写 Scenario Canon 或已提交历史；
- 为保持原剧本而撤销玩家选择；
- 无依据创建关键实体、线索或事件。

## 失败处理

- Director 调用失败时记录待处理任务；除非当前行动直接依赖其结果，否则不阻塞普通回合；
- 输出无法通过 schema 校验时丢弃候选并重试，不修改状态；
- 候选与领域约束或 Scenario Canon 冲突时拒绝候选并记录原因；
- 无法找到合理替代路径时，允许节点失败、休眠或进入替代结局；
- 建议包含不必要秘密时，必须经过 Visibility Policy 删除后才能交给 GM。

Director 的核心边界是：它不负责让预定剧情必然发生，而是在玩家已经改变世界之后，寻找仍然符合因果与剧本边界的可行剧情。
