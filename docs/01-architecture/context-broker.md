# Context Broker / 信息协调器

## 定位

Context Broker 是权威数据与任务上下文之间的受控查询边界。它把信息请求转换成可执行查询，完成实体解析、来源验证、版本检查和可见性过滤，再返回带来源的信息包。

Active Context Manager 判断哪些信息可能相关；Context Broker 判断这些信息是否存在、是否允许读取以及应返回哪个视图。Broker 不拥有事实，也不决定最终 Prompt 取舍。

## 输入与输出

请求至少包含任务、分支、状态版本、请求者、目标实体或事件、所需视图、请求原因和范围限制。名称只能作为检索线索，正式请求应尽快解析为稳定 ID。

返回的信息包至少保留：

- 已解析实体与视图类型；
- 来源状态、事件或可追源记忆；
- `branch_id` 与 `state_version`；
- 可见范围与已执行的裁剪；
- 信息新鲜度和失效键；
- 未找到、存在歧义或被拒绝的部分。

## 查询流程

1. 校验请求者、任务和请求范围。
2. 解析实体 ID；同名歧义无法可靠消除时返回候选或请求澄清。
3. 选择权威状态、事件、领域视图、关系索引或记忆作为来源。
4. 进行有限深度和数量的关系扩展。
5. 应用 Visibility Policy，移除请求者无权读取的信息。
6. 检查分支、状态版本、来源和派生视图新鲜度。
7. 返回最小充分的信息包，并可由程序装载到 Active Context Store。

确定性键查询和显式关系优先。只有实体消歧、语义检索或相关性无法可靠通过程序完成时，才可以调用模型辅助；模型结果仍须经过同样的来源和权限检查。

## 来源优先级

当前权威状态用于回答“现在是什么”；不可变事件用于回答“如何变成这样”；领域视图和关系索引用于定位；长期记忆用于压缩历史并提供来源入口。派生来源与权威数据冲突时，以权威状态和事件为准，并使派生条目失效。

## 权限与秘密

Broker 按任务而不是按组件名称授予最小视图。GM、Director、NPC 任务和开发调试任务可以拥有不同范围，同一实体也可以返回不同视图。拒绝越权请求时不得通过错误消息泄露秘密是否存在。

## 缓存与失效

Broker 可以读取派生视图和缓存，但缓存条目必须绑定来源版本与失效键。状态提交、分支切换、权限变化、来源纠正和实体关键状态变化都会触发失效。缓存未命中只影响性能，不影响事实可恢复性。

## 失败处理

- 必需来源不可用：返回明确缺口，由 Runtime 暂停相关操作。
- 非必需来源不可用：返回部分结果和缺失说明。
- 实体歧义：不按名称静默合并，交由请求者缩小范围。
- 版本过期：拒绝复用并重新查询。
- 越权：返回最小拒绝结果，不返回受限内容。
- 派生索引损坏：绕过或重建索引，从权威数据恢复。

## 禁止职责

Context Broker 不直接写入权威状态，不保存独立长期真相，不决定行动结果，不替代 Active Context Manager 评分，也不把完整数据库快照作为任务上下文返回。
