# 游戏循环与回合路由

## 设计目标

标准游戏循环必须同时满足以下目标：

- 玩家既可以选择 GM 提供的建议行动，也可以使用自然语言自由行动。
- 规则计算、随机结果和权威状态提交由程序负责，GM 不直接决定骰点或修改事实。
- 绝大多数普通回合只进行一次 GM 模型调用。
- Memory 和 Director 是逻辑职责，不是每回合必须同步调用的模型流水线。
- 每轮原始交互立即记录，信息可见性不依赖 Memory 已经完成异步整理。
- 复杂或含糊的机械自由行动可以进入较慢路径，但不能让所有回合承担同等成本。

系统不承诺任意复杂自然语言都能同时获得最低延迟、最低成本和规则级准确性。低成本通过回合分级实现，而不是用低可靠性的模型猜测玩家意图。

## 玩家输入原则

玩家声明角色想做什么，不负责声明使用哪个技能、难度或骰式。程序根据规则包、当前权威状态和行动条件决定：

- 是否需要检定；
- 检定公开还是秘密进行；
- 使用哪些属性、技能或对抗值；
- 难度、修正值、骰式和随机结果；
- 行动造成的候选状态变化能否提交。

玩家不需要在自由输入中使用 `/roll` 等机器指令。界面可以提供行动类型、实体引用、物品选择等可选辅助，但自然语言输入始终可用。

## 标准回合

一次能够产生游戏结果的标准回合为：

```text
GM 根据已提交状态建立局面并交出行动权
    ↓
玩家选择建议行动或输入自由行动
    ↓
回合路由器选择处理路径
    ↓
程序在需要时完成规则裁定、随机判定和原子提交
    ↓
GM 根据公开结果叙述新局面，并生成下一轮建议行动
```

GM 不能把未验证的候选变化叙述为既成事实。需要规则裁定或状态变化的行动，必须先由权威系统提交，再由 GM 叙述正式结果。

界面可以在等待期间显示由程序生成的处理状态，例如“正在处理：检查书桌”，但不需要为此额外调用 GM。处理状态不能提前宣布成功、失败或其他尚未提交的结果。

## 回合分级

### 第 0 级：纯角色扮演与对话

适用于不需要规则裁定，且没有立即权威状态变化的交谈、表态和表演性动作。

```text
玩家输入
    ↓
GM 调用一次
    ↓
GM 回复
```

此路径不为当前回合同步调用 Director、Memory、Information AI 或独立意图解析模型。玩家输入和 GM 输出由程序立即完整记录。GM 可以在同一次输出中按当前主持任务需要附带少量结构化旁路信息，但不得为了 Memory 强制生成语义摘要、承诺列表或关系标签；Memory 后台直接处理完整语义原文和程序生成的紧凑事实差异。

若 GM 在处理过程中发现行动实际上依赖规则裁定、关键状态变化或未公开事实，则必须转入相应机械行动路径，不能凭叙事直接决定结果。

### 第 1 级：结构化建议行动

GM 提供的建议行动除了玩家可见文案，还应携带结构化数据，例如行动类型、目标实体和明确方式。

```json
{
  "label": "仔细检查书桌上的暗格",
  "action": "investigate",
  "target_id": "desk_01",
  "approach": "careful"
}
```

玩家点击后，程序无需再次使用模型解析该输入：

```text
玩家点击建议行动
    ↓
程序验证前置条件、执行规则和掷骰、原子提交状态
    ↓
GM 调用一次，叙述结果并生成下一轮建议行动
```

结构化建议行动是最低成本、最高确定性的机械行动路径，但不构成玩家可行动范围的边界。

### 第 2 级：高置信度的简单自由行动

程序可以使用场景限定的保守匹配处理目标和动作均唯一的简单输入，例如“打开北门”“喝下治疗药水”。匹配依据可以包括：

- 当前场景允许交互的实体；
- 实体支持的动作及别名；
- 当前选中的目标或物品；
- 上一轮建议行动的语义别名；
- 规则包提供的有限动作词表。

只有同时满足以下条件时才能走快速路径：

- 行动唯一；
- 目标唯一；
- 不存在会改变行动性质的歧义；
- 不需要程序替玩家决定重大风险；
- 行动和目标通过当前状态的前置条件检查。

快路径宁可漏掉，也不能错判。程序无法高置信度匹配时必须退出本路径，不能通过宽松关键词映射擅自执行行动。

匹配成功后的流程与结构化建议行动相同：程序先裁定和提交，再调用一次 GM 叙述。

### 第 3 级：复杂或含糊的机械自由行动

复合行动、隐含目标、重大风险未说明或存在多种合理解释的输入进入较慢路径。例如：

> 我假装看画，等管家转身后撬开抽屉，同时留意走廊有没有人过来。

该路径不使用独立的低成本意图解析模型作为权威判断者。GM 在受约束的工具调用中表达对玩家意图的理解；程序仍负责选择规则、掷骰、验证和提交状态。工具返回正式的公开结果后，同一个 GM 任务继续生成叙述。

该 GM 任务也承担初始路由中无法由确定性快路径确认的自由文本理解。系统不得先运行一个读取完整上下文的 GM 分类任务，再启动另一个 GM 叙述任务；`action_intent`、`context_request` 和 `clarification` 都是同一任务中的受约束输出。

GM 只允许提交：

- 行动者和目标引用；
- 玩家明确表达的意图、方式和期望；
- 玩家明确接受的风险；
- 需要澄清的歧义。

GM 不允许提交：

- 成功或失败；
- 骰点、难度和最终使用的技能；
- 伤害、资源消耗和道具转移结果；
- NPC、场景或剧情节点的最终状态变化；
- 任意直接数据库修改。

如果玩家的重要选择不明确，程序不执行规则、不掷骰、不提交状态。GM 在本次调用中提出简短澄清问题，等待玩家下一次输入。

复杂机械自由行动允许比普通回合更慢。这是对任意自然语言自由、规则准确性和低平均成本之间的明确取舍，不应扩散为所有回合的固定开销。

## 检定类型

程序至少应区分以下处理方式：

- **无检定**：结果显而易见、没有压力，或失败不会产生有意义的区别。
- **公开检定**：玩家知道角色正在接受检定，界面可以显示采用的规则、骰点和结果。
- **秘密检定**：公开骰点会泄露隐藏信息，程序保存完整结果，但只向 GM 提供允许玩家感知的事实。
- **对抗检定**：由程序读取双方权威状态并计算结果。
- **被动检定**：由状态或事件触发，不要求玩家主动声明掷骰。

玩家只表达行动。检定类型由程序依据规则和场景决定。

## Memory 调度

Memory 不在每个回合中同步调用模型。即时捕获与长期整理分为两条通道：

1. **热通道**：程序每轮立即完整记录玩家输入和 GM 最终输出，并记录已提交事件与规则结果；近期原文可直接进入受限上下文。
2. **按需读取**：Information AI 或 GM 可以读取受限的近期未整理材料，不等待 Memory。
3. **冷通道**：程序只对结构化事实作无损差异压缩；完整语义原文按 Token 积压、场景结束、存档操作、即将退出近期窗口或空闲时间组成固定范围批次，交给 Memory 整理，不阻塞普通回合。
4. **长期使用**：整理结果作为可追源的派生记忆进入检索；原始记录继续保留并可用于核验。

长期整理任务绑定固定分支和回合范围。整理期间新回合继续写入；任务失败不能撤销已经提交的游戏回合，未整理材料继续保留并可被按需读取或稍后重试。

Memory 任务优先级低于当前 GM、当前回合必需的信息请求和必要上下文准备。异步不表示可以占用前台预留的并发、速率额度或本地算力；单并发环境只在前台空闲窗口运行 Memory。Memory 可以落后若干回合或一个场景，但程序必须监控处理游标和积压，保证材料在退出近期窗口前进入待处理批次。

## Director 调度

Director 不在每个回合中同步调用模型。程序先运行 Scenario Runtime 与 Story Monitor，处理节点条件、结构可达性、线索覆盖和明确替代路径。只有结构结果仍存在语义或因果缺口时才调度 Director，例如：

- 进入或离开场景；
- 获得、失去或破坏关键线索和道具；
- 关键 NPC 的状态发生变化；
- 剧情节点条件改变后，叙事上的可行性仍无法确定；
- 所有作者定义路径均受阻，需要有来源的替代机会；
- 玩家目标与现有剧情线发生语义偏离；
- 长时间没有有效推进，且结构化覆盖检查无法解释原因。

只有命中需要语义或因果判断的重要触发器时，才调用 Director。普通对话、普通观察和已知规则行动不因“每回合惯例”调用 Director。

相邻触发按受影响节点和状态版本合并。普通评估只为后续回合准备；路径修复可以提高后台优先级，但不阻塞当前 GM。Director 输出的机会必须在进入 GM 上下文前重新检查版本、条件、场景、失效键与可见范围。

Director 只能提出有来源的剧情候选变化、未来预测、GM 引导和预加载提示。Information AI 判断哪些可选信息值得准备，Context Broker 执行来源、权限、版本和预算检查。候选必须由确定性系统验证并提交后，才能作为已发生事实进入 GM 上下文；预测只能作为幕后引导。

## 成本基线

正常运行时，各类回合的同步模型调用目标如下：

| 回合类型 | GM | Information | Memory | Director | 独立解析模型 |
| --- | ---: | ---: | ---: | ---: | ---: |
| NPC 对话或普通 RP | 1 | 0 或按需 | 0 | 0 | 0 |
| 点击建议行动 | 1 | 0 或按需 | 0 | 0 或按触发调用 | 0 |
| 简单自由行动 | 1 | 0 或按需 | 0 | 0 或按触发调用 | 0 |
| 复杂机械自由行动 | 1 个工具调用闭环 | 0 或按需 | 0 | 0 或按触发调用 | 0 |
| 剧情节点发生重要改变 | 1 | 按候选或预取需要 | 0 | 1 | 0 |
| 场景结束或批量整理 | 按需要 | 按需要 | 0 或 1 | 0 或 1 | 0 |

这里的数字是架构目标，不是供应商计费承诺。带工具调用的 GM 任务会在工具调用前后分段生成，因此通常比普通单段 GM 回复更慢，但不应退化为两个独立 GM 读取完整上下文的固定流水线。

## 失败与降级

- 程序裁定或原子提交失败：不生成正式结果叙述，保留待处理回合并允许安全重试。
- GM 在状态提交后生成叙述失败：可以根据同一已提交结果重试叙述，不能重复裁定或重复提交。
- 快路径匹配不确定：退出快路径，进入复杂行动或澄清路径，不执行猜测结果。
- Information AI 失败：使用权威状态、确定性基础上下文、近期原始交互和已有记忆降级继续；需要语义事实才能安全行动时请求澄清。
- Director 或长期 Memory 任务失败：记录任务并延后重试；近期原始信息仍可读取，除非当前行动直接依赖其结果，否则不阻塞普通回合。
- GM 叙述与已提交状态冲突：权威状态保持不变，进入叙事纠正或异常处理，不能修改状态迁就叙事。

## 验收标准

- 普通 RP、结构化建议行动和高置信度简单自由行动不调用独立意图解析模型。
- 普通回合只调用一次 GM；只有复杂机械自由行动允许进入 GM 工具调用闭环。
- 确定性快路由无法确认的自由文本直接进入单一 GM 任务，不经过独立的 GM 意图分类调用。
- 相同权威状态、规则、输入和随机种子产生相同的程序裁定结果。
- GM 无法通过模型输出直接写入骰点、规则结果或权威状态。
- 模糊的重大行动不会被关键词误判并直接执行。
- Information、Memory 和 Director 不因固定回合流程被无条件调用。
- Memory 尚未整理的近期交互仍可由受限查询进入当前任务上下文。
- GM 叙述失败后的重试不会重复掷骰、重复消耗资源或重复提交事件。
- 开发调试视图可以展示提交后 Information / Director / Memory 流水，但必须默认关闭，且不得把未确认候选显示为已发生事实。
