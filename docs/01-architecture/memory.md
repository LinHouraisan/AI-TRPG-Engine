# Memory AI / 长期记忆整理

## 定位

Memory AI 把玩家输入、GM 最终输出、已提交事件和状态整理成便于后续检索的长期记忆候选，关注重要事实、因果、承诺、关系变化、玩家意图和未解决事项。它减少重复阅读完整历史的成本，但不负责保证信息即时可见，也不替代原始交互记录、事件日志或当前权威状态。

程序在每回合立即完整记录玩家输入、GM 最终输出和已提交结果。Memory 可以延后异步整理；在整理完成前，GM 和 Information AI 仍可按权限读取受限的近期原始记录。即时连续性由 Recent Interaction Buffer 保证，不要求 Memory 与 GM 同步推进。

## 调用时机

Memory 不按每回合固定调用。典型触发包括未整理语义文本达到 Token 预算、场景结束、保存检查点、同一批近期材料被反复检索、材料即将退出近期窗口，以及模型资源空闲。程序只能决定批次边界，不能因为文本看似不重要而将其排除在长期整理之外。

任务绑定固定的分支和回合范围，并使用持久化处理游标记录原始材料已经整理到哪个回合。新回合可以继续记录，不等待旧任务完成；任务成功后原子推进游标，失败不推进。相邻批次可以携带少量已处理原文作为只读重叠上下文，并明确禁止由重叠部分重复创建记忆。

Memory 是低优先级后台任务。当前 GM、当前回合必需的规则与信息请求、下一回合的必要上下文准备均优先于 Memory。单并发 Provider 或本地模型只在前台空闲窗口启动 Memory；尚未开始的任务在新 GM 请求到达时延后，运行中的任务只有在 Provider 支持安全取消时才可抢占。

开发调试可以显示 extract/consolidate 是否走了模型、游标推进到哪一回合。该视图默认关闭，不是玩家功能。

## 输入

Memory 输入分为两条通道：

- **语义通道**：批次范围内完整的玩家原始输入、GM 最终叙事、NPC 台词、澄清问题与玩家回答。程序不得对这些文本作重要性筛选、关键词删减或语义概括。
- **事实通道**：程序从已提交事件、mutations 和规则结果生成的无损紧凑差异，包括实体引用、变化字段、因果引用、状态版本、场景、时间和可见范围。

程序可以从事实通道删除重复的完整前后状态、重复实体正文和规则载荷，只保留能够回到权威来源的差异与引用。它不能用程序摘要替代语义通道。Memory 还可以读取与当前批次直接相关的 active 记忆及其来源，但不读取完整世界状态、完整规则包、完整历史记忆、GM Prompt 或 Director 原始分析。

来源必须保留其语义等级：已提交事件可以整理为事实；玩家和 GM 文本只能提取为陈述、意图、承诺、角色认知或待验证候选；Director 预测只能整理为幕后预测，不能因此变成已经发生的事实。

GM 不需要为 Memory 强制生成 `memory_candidates`、承诺列表、关系标签或检索关键词。此类旁路信息存在时只能作为定位提示，不能替代 Memory 对完整语义文本的处理，也不能成为记忆完整性的前提。

## 记忆候选

候选应区分事实摘要、因果链、角色承诺、关系变化、未解决问题和叙事连续性，并至少包含：

- 来源事件或状态版本；
- 涉及实体与时间范围；
- 所属分支和可见范围；
- 记忆类型、重要性和检索线索；
- 对旧记忆的补充、更正、合并或失效建议。

自然语言摘要中的断言必须能够回到来源。不能可靠追源的内容只可作为待核查线索，不进入正式长期记忆视图。

## 整理与合并

程序先校验来源、版本和权限，再接受派生记忆；涉及权威状态变化的语义候选交给 Information AI 消歧和归类，再由确定性事实内核决定能否提交。多个事件和交互可以合并为更高层摘要，但原始记录不删除。新事实推翻旧认知时，应保留旧记忆曾在何时有效，并通过新来源标记更正或失效，不能静默改写历史。

记忆可以分层保存：近期事件摘要、场景摘要、角色与关系摘要、剧情因果和战役概览。较高层摘要用于定位，关键裁定仍需回查权威来源。

新材料提取与长期摘要合并使用不同任务契约。`memory.extract` 只处理尚未整理的固定范围，提取新的事实摘要、因果、承诺、关系、目标和未解决事项；`memory.consolidate` 只在场景结束、同类记忆积累或后台空闲时增量更新场景、角色和战役摘要，不因每次 extract 重写全部长期摘要。

## 可见性

同一事件可以产生面向不同任务的记忆视图。玩家已知、NPC 已知、GM 可叙事和幕后剧本信息不得混成一个无权限边界的摘要。分支之间也不得复用带有另一时间线结果的记忆。

## 与 Active Context 的关系

Memory 提供可检索的长期派生材料；近期原始交互提供尚未整理的热信息；Context Broker 校验并取回允许视图。每条记忆除摘要外还应提供涉及实体、场景、时间范围、记忆类型、检索键、未解决话题、重要性、可见范围和来源，使程序能够完成基础上浮。

Memory 条目提交后，程序立即更新检索索引，并将涉及当前场景、活跃实体、玩家目标或未解决话题的条目加入下一轮候选工作集。Information AI 在后台判断更隐含的跨实体、跨场景和语义关联，不是长期记忆进入 GM 上下文的必经中介。记忆整理进度不会阻止近期信息进入任务上下文，记忆被淘汰或重建也不会改变权威状态。

## 失败处理

- 模型失败：记录整理任务并稍后重试，不阻塞普通回合。
- 后台积压：保留近期原文可读性，扩大后续批次并暂停更低优先级的合并任务，不抢占 GM 前台资源。
- 来源缺失或版本不符：拒绝对应候选。
- 摘要与权威事实冲突：使摘要失效并从来源重建。
- 合并结果泄露秘密：按可见范围拆分或拒绝。
- 记忆存储损坏：从事件与状态重新生成，允许暂时降低检索质量。

## 禁止职责

Memory AI 不删除原始交互或事件，不直接修改实体状态，不决定规则或剧情结果，不把玩家陈述、GM 文本或 Director 预测自动升级为事实，不创造无来源信息，不维护与本地权威数据竞争的私有历史，也不保证模型自然语言摘要本身绝对正确。
