# Memory AI / 长期记忆整理

## 定位

Memory AI 把已提交事件和状态整理成便于后续检索的长期记忆候选，关注重要事实、因果、承诺、关系变化和未解决事项。它减少重复阅读完整历史的成本，但不替代事件日志或当前权威状态。

## 调用时机

Memory 不必每回合同步调用。典型触发包括场景结束、累计一定事件、关键关系或承诺变化、保存检查点、上下文反复缺失，以及低优先级后台整理任务。调用失败通常不阻塞当前回合。

## 输入

Memory 只处理已经提交且与任务相关的材料：事件、前后状态、规则裁定、已有记忆及其来源、当前分支和可见范围。未验证的 GM 叙事、Director 建议或领域候选不能被整理成正式记忆。

## 记忆候选

候选应区分事实摘要、因果链、角色承诺、关系变化、未解决问题和叙事连续性，并至少包含：

- 来源事件或状态版本；
- 涉及实体与时间范围；
- 所属分支和可见范围；
- 记忆类型、重要性和检索线索；
- 对旧记忆的补充、更正、合并或失效建议。

自然语言摘要中的断言必须能够回到来源。不能可靠追源的内容只可作为待核查线索，不进入正式长期记忆视图。

## 整理与合并

程序先校验来源、版本和权限，再接受记忆候选。多个事件可以合并为更高层摘要，但原事件不删除。新事实推翻旧认知时，应保留旧记忆曾在何时有效，并通过新来源标记更正或失效，不能静默改写历史。

记忆可以分层保存：近期事件摘要、场景摘要、角色与关系摘要、剧情因果和战役概览。较高层摘要用于定位，关键裁定仍需回查权威来源。

## 可见性

同一事件可以产生面向不同任务的记忆视图。玩家已知、NPC 已知、GM 可叙事和幕后剧本信息不得混成一个无权限边界的摘要。分支之间也不得复用带有另一时间线结果的记忆。

## 与 Active Context 的关系

Memory 提供可检索的长期派生材料；Context Broker 校验并取回允许视图；Active Context Manager 决定当前任务是否需要装载。记忆被淘汰或重建不会改变权威状态。

## 失败处理

- 模型失败：记录整理任务并稍后重试，不阻塞普通回合。
- 来源缺失或版本不符：拒绝对应候选。
- 摘要与权威事实冲突：使摘要失效并从来源重建。
- 合并结果泄露秘密：按可见范围拆分或拒绝。
- 记忆存储损坏：从事件与状态重新生成，允许暂时降低检索质量。

## 禁止职责

Memory AI 不删除原始事件，不直接修改实体状态，不决定规则或剧情结果，不创造无来源事实，不维护与本地权威数据竞争的私有历史，也不保证模型自然语言摘要本身绝对正确。
