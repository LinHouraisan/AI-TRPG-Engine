# Active Context / 临时上下文系统

> Active Context 是核心上下文管理子系统，不是普通的无状态缓存；但其中保存的数据仍然是可重建的派生数据，不构成新的权威事实源。

## 定位与目标

Active Context 为 GM、Director 和其他 AI 任务维护一组范围有限、版本明确、经过权限过滤的高相关信息。

它解决的问题是：在不向模型发送完整世界数据的前提下，持续、可靠地提供完成当前任务所需的信息。

主要目标：

- 减少模型输入 Token；
- 降低上下文组装延迟；
- 避免每次调用都扫描完整世界数据；
- 为基本无状态的模型提供稳定的局部工作上下文；
- 保持实体、事件和记忆的来源关系；
- 防止过期信息和秘密信息进入错误的模型任务；
- 允许模型在信息不足时按需补充。

Active Context 不保存长期真相。权威状态发生变化后，旧数据必须失效、刷新或重新验证。

## 组成

### Information AI / 信息 AI

负责异步预判后续 GM 任务可能需要哪些可选信息、识别仅靠实体与关系索引无法发现的语义关联，并建议哪些信息应加入、保留、降级或淘汰。它还可以解释 Memory 提出的语义候选，但信息整理与上下文准备是不同任务契约。

Information AI 默认在 GM 生成、玩家阅读或等待输入等后台窗口为下一回合准备信息，不作为普通回合开始前的同步步骤。普通回合即使尚未获得其建议，也能使用确定性基础上下文、近期原始交互和已有记忆继续。

信息 AI 只能输出事实变化 Proposal 或上下文计划，不能直接读取或写入权威数据与临时存储。

### Context Broker

负责执行实体与关系查询、来源解析、状态和分支检查、Visibility Policy 过滤、上下文装载、按需补充以及失效数据刷新。

Context Broker 是 AI 与数据系统之间的受控入口。

### Active Context Store

保存已经装载、可供后续任务选择的信息，包括结构化实体视图、近期事件、受限的近期原始交互、长期记忆、关系、叙事约束、幕后预测、来源引用、状态版本和可见范围。

Store 是可重建的局部工作集，不是权威数据库。

## 上下文隔离

Active Context 不能是所有 AI 共享的一份全局信息集合。上下文至少按以下范围隔离：

- `branch_id`：当前时间线分支；
- `state_version`：所依据的状态版本；
- `scene_id`：当前场景；
- `audience`：GM、Director 或其他 AI 角色；
- `task_id`：当前模型任务；
- `visibility_scope`：允许读取的秘密等级。

GM、Director 和 Information AI 使用不同视图：

- GM 只能读取玩家可见信息，以及当前叙事所必需、经过过滤的场景秘密；
- Director 可以读取当前剧本分析所需的 Scenario Canon 和剧情秘密；
- Director 的完整上下文不能直接复用为 GM 上下文；
- Director 建议必须经过 Visibility Policy 转换后才能进入 GM 上下文。
- Information AI 只读取当前事实解释或上下文规划任务需要的范围，不能借管理职责获得全局秘密。

## 可能包含的信息

Active Context Store 可以包含：

- 当前玩家角色及相关状态；
- 当前 SceneDefinition 的允许视图和当前 SceneState；
- 当前正式 NPC 及其受限视图；
- 当前可交互的 Item；
- 当前可用或受影响的 ScenarioNode 和 `StoryProgress`；
- 最近关键事件和当前行动依赖的规则结果；
- 当前关系和知识边界；
- 与当前场景有关的世界时间和地点状态；
- 必要的近期对话与叙事连续性；
- 带来源的长期记忆；
- Director 当前关注的问题；
- Director 提供的高概率发展、预加载提示和经过过滤的 GM 引导；
- 当前任务的叙事约束和未解决上下文请求。

“当前世界状态”只表示与当前任务相关的受限视图，不是完整世界快照。

## 上下文条目

每个上下文条目至少记录：

- `entry_id`；
- `entity_id` 或 `event_id`；
- `view_type`；
- `branch_id`；
- `state_version`；
- `visibility_scope`；
- `source_refs`；
- `load_reason`；
- `relevance_score`；
- `token_estimate`；
- `loaded_at`；
- `invalidation_keys`；
- `retention_class`。

`source_refs` 必须能够定位权威状态、原始事件、原始交互或可追源记忆。Director 预测还必须保留其预测身份和依据，不能作为已发生事实进入模型任务。

## 信息进入机制

信息按以下顺序进入 Active Context。

### 确定性基础装载

程序首先装载当前任务必需的信息，包括当前玩家、场景、行动者、目标、状态版本、近期提交结果、可交互实体、必要的近期原始对话、未解决行动和权限范围。基础装载不依赖 Memory 整理进度或模型判断。

### 未整理近期信息

玩家输入、GM 最终输出、已提交事件和结构化旁路信息在每回合立即记录。长期记忆尚未生成时，Context Broker 可以按实体、回合范围和来源取回最小的近期原始片段，供 Information AI 或 GM 使用。读取原始交互只是弥补异步整理延迟，不会把其中的自然语言自动升级为权威事实。

### 场景与关系扩展

Context Broker 根据确定性关系进行有限扩展，例如当前场景中的实体、实体的持有者或位置、NPC 已知事实、节点依赖线索和近期事件直接关联的实体。

关系扩展必须限制深度和数量，不能无边界遍历关系网络。

### 事件触发预取

Runtime 可以在进入新场景、获得关键道具、关键 NPC 状态改变、剧情节点条件改变或当前行动引用未装载实体时预取信息。

Director 可以根据玩家行为和世界走向提出高概率发展与预加载提示。Information AI 判断这些提示对哪些任务值得准备，Context Broker 再执行来源、版本、权限和预算检查。预测性材料始终标记为预测，并在容量不足时优先淘汰。

Memory 提交新条目时，程序按其实体、场景、时间范围、记忆类型、检索键、重要性和可见范围更新索引。涉及当前场景、活跃实体、玩家目标或未解决话题的条目自动进入候选工作集；Information AI 可以在后台补充跨实体、跨场景和隐含话题关联。上浮过程先装载短摘要与来源引用，只有任务确实需要精确细节时才展开正文或原始来源。

### 显式请求

GM、Director 或其他 AI 可以提交 `context_request`，说明当前任务、请求原因、相关实体和所需视图。Context Broker 判断请求是否相关、是否允许以及返回范围。

### Information AI 相关性建议

Information AI 可以输出 `context_plan`，建议加载、保留、降级或淘汰哪些信息。建议必须经过 Context Broker 的来源、版本、权限和预算检查后才能执行。

AI 不能绕过 Context Broker 直接写入 Active Context Store。

`context_plan` 面向后续任务，不应暂停当前普通 GM 回合等待完成。确定性关联保证必需信息和显式相关记忆能够上浮；Information AI 负责提高隐含语义关联的召回率，不能成为长期记忆进入 GM 上下文的唯一入口。

## 当前快照与后台准备

每个 GM 任务读取绑定 `task_id`、`branch_id` 和 `state_version` 的不可变 Turn Snapshot。任务执行期间，后台更新不得改变该快照。

场景工作集使用双缓冲：当前版本供正在执行的任务读取，准备版本接收 Information AI 建议、Memory 新条目和事件触发预取。准备版本完成来源、权限、版本与预算检查后原子切换，供下一任务选择。准备失败或尚未完成时，Runtime 不等待它，改用当前有效工作集与确定性基础装载。

GM 默认通过一次普通 Chat 使用已经准备好的 Turn Snapshot。`context_request` 或工具补查只处理玩家突然引入未预取实体、精确来源核验等低频缺口，不能替代后台准备成为常规取数方式。

## 信息失效与淘汰

### 强制失效

发生以下情况时，相关条目必须失效或重新验证：

- 权威状态发生相关变化；
- 切换分支或检查点；
- 当前场景结束；
- 实体的位置、持有者、生死或知识状态变化；
- ScenarioNode 状态变化；
- Visibility Policy 变化；
- 来源事件被纠正；
- 当前任务或权限范围结束。

失效优先于相关性评分。高相关但已经过期的信息也不能继续使用。

### 容量淘汰

容量不足时按以下顺序保留：

1. 当前行动必需的权威状态；
2. 当前回合已经提交的结果；
3. 当前场景和直接交互实体；
4. 当前任务依赖的规则与剧情约束；
5. 近期关键事件；
6. 相关长期记忆和关系；
7. 近期对话和叙事连续性信息；
8. Director 预测与其他推测性预取信息。

优先淘汰低相关、仅因最近访问而保留、可快速重查、未被使用的预取信息，以及被更高版本取代的信息。淘汰不会删除权威来源。

## 保留等级

条目分为：

- **Pinned**：当前任务必需，不允许因容量压力淘汰；
- **Active**：高相关，正常保留；
- **Deferred**：保留来源，需要时再展开；
- **Prefetched**：推测可能使用，容量不足时优先淘汰。

体积较大的实体或记忆可以只保留引用和简要索引，需要时再请求完整的允许视图。

## 容量与 Token Budget

Active Context Store 容量和单次 Prompt Token Budget 是两个不同限制。

### Store Budget

控制工作集可以保留多少结构化条目和材料。Store 可以大于一次模型调用能够使用的上下文。

### Prompt Budget

控制一次模型任务实际选入多少内容。必须先为系统指令、输出契约、工具定义、玩家输入、必需状态和模型输出预留空间，剩余预算才用于实体、事件、记忆和 Director 建议。

早期不固定统一 Token 数值，应通过以下指标实验确定：

- 上下文缺失率和按需补充次数；
- 无效装载比例和 Prompt 截断次数；
- 信息过期命中次数；
- 平均输入 Token；
- 首次响应和完整回合延迟；
- GM 叙事与权威状态冲突率。

容量不足时先减少低优先级派生信息，不能删除当前行动必需的状态或权限约束。

## 与 Prompt Context 的关系

```text
Authoritative Data
├── Current State Store
└── Immutable Event Log
          │
          ▼
Context Broker
├── 来源解析
├── 版本检查
└── Visibility Policy
          │
          ▼
Active Context Store
├── GM Context View
├── Director Context View
└── 其他任务视图
          │
          ▼
Task-specific Selection
          │
          ▼
Prompt Context
          │
          ▼
Model Call
```

- **Authoritative Data** 保存正式事实和历史；
- **Active Context Store** 保存经过过滤、可重建的局部工作集；
- **Prompt Context** 是从工作集中为某一次模型调用选择的只读输入快照。

Prompt Context 必须绑定 `task_id`、`branch_id`、`state_version`、`audience` 和所使用条目的来源清单。模型输出绑定相同版本，不能用旧 Prompt 的结果直接修改新状态。

## 一致性要求

- 权威状态提交后，相关条目必须失效或刷新；
- 同名实体不能仅凭名称合并，必须使用实体 ID；
- 不同分支、任务和可见范围的上下文不能混用；
- 长期摘要不能覆盖结构化权威状态；
- 信息冲突时以权威状态和事件为准；
- Prompt 构建时必须再次检查版本和权限；
- AI 输出引用的上下文版本过期时，不得直接提交其候选变化。

## 失败处理

- Information AI 调用失败或准备版本未完成：使用当前有效工作集、确定性基础上下文、近期原始交互和已有长期记忆继续，不阻塞普通回合；
- Context Broker 查询失败：必需信息缺失时暂停相关操作，非必需信息可以省略；
- 请求越权：拒绝请求并只返回允许使用的最小信息；
- 条目过期：重新查询，不把旧条目发送给模型；
- Store 容量不足：淘汰低优先级派生信息，保留 Pinned 条目；
- Prompt 超出预算：降低可选信息层级，不截断必需状态和权限约束；
- 来源无法验证：拒绝条目进入 Prompt Context；
- 分支或权限不匹配：拒绝复用对应上下文。

Information AI 异步预判哪些可选信息值得为后续任务准备，程序保证显式相关信息与长期记忆的基础上浮，Context Broker 决定哪些信息能够读取，Active Context Store 保存经过验证的局部工作集，而每次 Prompt 只从当前稳定快照中选择真正需要的内容。Memory 是否已经完成后台整理、Information AI 是否已经完成下一轮预测，都不构成当前信息可见性的前置条件。
