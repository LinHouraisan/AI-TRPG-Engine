# 信息 AI 与确定性事实内核

## 定位

系统不再为 NPC、Item、Scene、World 和 Scenario 分别设置领域 Analyzer。开放语义、角色动机、世界影响、候选事实归类和上下文相关性统一由 Information AI / 信息 AI 处理；多个任务可以共享同一模型，但必须使用各自的输入范围和输出契约。

领域差异仍然存在于结构化状态、事件语义和确定性约束中，但不要求对应独立 AI、服务或厚重领域对象。程序可以用通用实体、组件、命令、事件和声明式约束承载这些差异，只为无法声明表达的复杂不变量保留最小验证逻辑。

## 信息 AI 的职责

信息 AI 负责：

- 解释开放自然语言对当前人物、道具、场景、世界和剧情的含义；
- 对 Memory 提取的语义候选进行消歧、去重、归类和持久化价值判断；
- 区分已发生事实、角色认知、意图、推断、预测和待确认信息；
- 把有来源的语义判断转换成结构化事实变化 Proposal；
- 判断当前任务需要装载、保留、降级或淘汰哪些可选信息；
- 根据 Director 的高概率发展和预加载提示准备后续可能使用的信息。

信息 AI 的判断只是候选。它不能决定数据库操作，也不能把置信度高的推断当作已经发生的事实。

## 即时信息与长期记忆

信息 AI 不依赖 Memory AI 先完成整理。玩家输入、GM 最终输出、已提交事件和必要的结构化旁路信息由程序立即记录；信息 AI 可以按任务范围读取尚未整理的近期交互，也可以读取已经生成的长期记忆。

Memory AI 负责异步压缩和长期整理，信息 AI 负责在当前任务中解释、选择和使用信息。两者之间的关系是“原始记录始终可读，长期记忆降低后续读取成本”，而不是“Memory 完成后信息才可见”。

## 确定性事实内核

以下工作必须由程序完成：

- 标识、引用、数量、位置、持有、容器和版本检查；
- 生命、资源、耐久、充能、状态效果和随机结果计算；
- 规则条件、剧情节点条件、时间触发和状态转换；
- 权限过滤、来源检查、关系索引更新和原子提交；
- 幂等、并发冲突、事件重放及跨实体一致性；
- 已有明确规则和约束的合法性检查。

程序内核接受结构化 Proposal，依次检查 schema、引用、权限、状态版本、规则和不变量，通过后才生成并提交正式事件与状态变化。

## 输入与候选输出

信息 AI 只读取 Context Broker 提供的任务受限视图。输出至少说明：

- 依据的原始交互、事件、实体和状态版本；
- 信息属于事实、认知、意图、推断、预测还是待确认内容；
- 建议的结构化变化及其前置条件；
- 不确定部分和需要澄清的问题；
- 可能影响的其他实体或剧情；
- 禁止泄露的信息。

候选不得包含直接数据库操作。跨多个实体的建议由 Runtime 组织为同一提交候选，并由确定性事实内核统一校验。

## 与 GM、Director 和 Memory 的区别

- GM 面向玩家理解和表达当前局面，使用已经准备好的任务上下文。
- Director 推演未来剧情和世界走向，提出剧情候选、GM 引导和预加载提示。
- Memory 从历史交互中提取、压缩和整理长期派生记忆。
- Information AI 解释候选信息、提出结构化事实 Proposal，并管理可选信息的相关性与临时工作集。

这些名称表示逻辑职责，不要求使用四个独立模型。职责可以共享模型，但输入视图、权限和输出契约不能混用。

## 降级与失败

- 信息 AI 不可用时，确定性规则、当前权威状态、近期原始交互和基础上下文继续可用；
- 语义候选无法验证时拒绝候选，必要时向玩家澄清；
- 多个候选冲突时由权威事实、规则和程序约束裁决，仍无法确定时不提交；
- 输出引用过期版本时丢弃并重新构建任务上下文；
- 临时信息计划失败时使用程序装载的必需信息继续，降低表现质量但不改变事实。

## 禁止职责

信息 AI 不直接写入 State Store、Event Log 或 Active Context Store，不自行掷骰，不绕过规则推进剧情节点，不修改不可变定义，不读取超出任务范围的秘密，也不维护无法从原始交互、权威状态、事件或可追源记忆重建的私有事实。
