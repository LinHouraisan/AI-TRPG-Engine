# 领域 AI 与确定性领域模块

## 定位

NPC、Item、Scene、World 和 Scenario 等领域首先是确定性领域模块。模块维护领域约束、查询视图和候选校验；只有在语义、角色动机或开放世界影响难以通过规则可靠表达时，才附加可选的 AI Analyzer。

领域 AI 是分析能力，不是状态所有者。一个模型可以承担多个 Analyzer，同一 Analyzer 也可以按任务选择不同模型。

## 何时使用程序

以下工作优先由程序完成：

- 标识、数量、位置、持有、容器和版本检查；
- 生命、资源、耐久、充能与状态效果计算；
- 规则条件、剧情节点条件和时间触发；
- 权限过滤、关系索引更新和原子提交；
- 已有明确领域规则的合法性检查。

不应为了“使用 AI”而把可确定计算改成模型判断。

## 何时使用 Analyzer

Analyzer 可以用于解释开放自然语言对领域的含义、评估 NPC 目标与已知信息、提出世界后果、识别场景语义变化或补充作者未枚举但符合现有事实的候选。调用应由实际事件和不确定性触发，而不是固定每回合执行。

## 输入与候选输出

Analyzer 只读取 Context Broker 提供的任务受限视图。输出至少说明：

- 依据的事件、实体和状态版本；
- 分析结论与不确定部分；
- 建议的领域变化及其前置条件；
- 可能影响的其他领域；
- 禁止泄露或仍需确认的信息。

候选不得包含直接数据库操作，也不能把推断写成已经发生的事实。

## 领域所有权

- NPC Domain 校验 NPC 状态、知识、目标、关系和承诺。
- Item Domain 校验道具实例、持有、容器、数量和状态。
- Scene Domain 校验场景运行状态与可交互内容。
- World Domain 校验时间、地点状态和跨场景影响。
- Scenario Domain 与 Scenario Runtime 校验剧情节点和 `StoryProgress`。

跨领域建议应拆分为各领域候选，并由 Runtime 在同一事务中组织校验。一个 Analyzer 不能越过目标领域直接决定其状态。

## 与 GM、Director 和 Memory 的区别

GM 负责面向玩家的理解与叙事；Director 分析剧情路径；Memory 整理已发生历史；领域 Analyzer 分析某一领域可能如何响应。职责可以共享模型，但输入视图、输出契约和校验边界必须分开。

## 降级与失败

- Analyzer 不可用时，确定性规则和已定义内容继续运行。
- 语义候选无法验证时拒绝候选，必要时向玩家澄清。
- 多个候选冲突时由领域约束和权威事实裁决，不按模型置信措辞决定。
- 输出越权或引用过期版本时丢弃并重新构建上下文。
- 某领域没有 Analyzer 时，不影响该领域作为确定性模块存在。

## 禁止职责

领域 AI 不直接写入 State Store 或 Event Log，不自行掷骰，不推进剧情节点，不修改不可变定义，不读取超出任务范围的秘密，也不维护无法从权威数据重建的私有事实。
