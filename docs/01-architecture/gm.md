# GM AI

## 定位

GM AI 是玩家直接接触的主要叙事与交互 AI。它负责理解玩家表达，并将已经提交的游戏结果转换成连贯的玩家视角叙事。

GM AI 不是权威状态的所有者，也不是规则裁定者。它不能通过叙事、工具调用或结构化输出直接决定游戏事实。

## 职责

GM AI 负责：

- 根据已经提交的状态描述当前场景；
- 扮演当前场景中的 NPC；
- 接受建议行动和自由自然语言行动；
- 在复杂机械行动中表达对玩家意图的理解；
- 在重要选择存在歧义时请求澄清；
- 根据已经提交的规则结果回应玩家行为；
- 生成带结构化数据的建议行动；
- 使用 Active Context Store 中已经装载的信息；
- 通过受约束的工具向 Context Broker 请求补充信息；
- 使用经过权限过滤的 Director 建议和场景秘密。
- 使用少量近期原始对话保持指代、语气和文本衔接。

“回应玩家行为”不表示 GM 可以自行决定行为结果。需要规则裁定或状态变化的行动，必须先由 Runtime 完成裁定和提交，再由 GM 生成正式叙事。

## 可知信息与秘密边界

GM AI 只能读取完成当前交互和叙事任务所必需的信息，包括：

- 玩家角色可以感知的当前场景；
- 已公开的人物、地点、道具、事件和规则结果；
- 玩家角色已知的相关记忆；
- 当前 NPC 可以说出的知识、可见态度和行为倾向；
- 经过过滤的 Director 建议；
- 当前叙事所必需、经过过滤的场景秘密；
- Active Context Store 中经过权限和版本检查的信息。

场景秘密应尽量转换成“可以如何表现”和“禁止透露什么”的叙事约束，而不是向 GM 提供完整幕后事实。

GM AI 不应读取：

- 完整剧本答案或尚未触发的剧情节点；
- 与当前场景无关的幕后信息；
- NPC 完整秘密、长期计划或其无权知道的信息；
- 未来事件的确定结果；
- 未经过 Context Broker 和 Visibility Policy 过滤的数据。

Director 的原始分析可能包含秘密，不能直接进入 GM 上下文。交给 GM 的建议只能包含当前可采用的叙事方向、伏笔、行动机会和禁止提前透露的信息。

## 禁止职责

GM AI 不负责：

- 决定行动成功或失败；
- 选择最终规则、技能、难度或修正；
- 生成或修改骰点及其他随机结果；
- 计算伤害、资源消耗或状态效果；
- 直接修改 NPC、道具、场景、世界或剧情状态；
- 直接推进、完成或废止 ScenarioNode；
- 把 Director 建议当成已经发生的事实；
- 绕过 Context Broker 读取权威数据；
- 保存与本地状态竞争的长期私有真相；
- 决定长期记忆的最终保留或遗忘；
- 使用玩家或 NPC 不知道的信息替其行动；
- 为了叙事连贯而修改已经提交的事实；
- 在信息不足时补全关键设定。

如果叙事需要一个不存在于权威状态中的新事实，GM 只能提出候选或请求澄清，不能把它描述为既成事实。

## 输出契约

GM 输出分为四种类型。一次输出只能采用一种类型。

### `clarification`

用于玩家的重要选择存在歧义时。至少包含：

- `message`：需要玩家确认的问题；
- `choices`：可选的结构化选择，可以为空。

发出澄清请求时，系统不得执行规则、生成随机结果或提交状态变化。

### `context_request`

用于当前上下文不足时。至少包含：

- `reason`：信息与当前任务的关系；
- `entities`：需要查询的实体 ID；
- `requested_views`：请求的受限信息视图。

GM 不能请求完整剧本、NPC 全部秘密、未触发节点或与当前任务无关的信息。

### `action_intent`

用于复杂机械行动。可以包含：

- 行动者和目标实体 ID；
- 玩家明确表达的行动、方式和目标；
- 玩家明确接受的风险；
- 仍需澄清的歧义。

`action_intent` 不能包含成功或失败、最终技能、难度、骰点、伤害、资源消耗，以及 NPC、道具、场景、世界或剧情的最终变化。

### `narration`

用于 Runtime 已经完成裁定和原子提交之后。至少包含：

- `turn_id`；
- `state_version`；
- `narrative`；
- `suggested_actions`。

正式叙事必须只描述绑定状态版本中的玩家可见事实。建议行动应包含玩家文案和可供 Turn Router 使用的结构化行动数据，不得泄露未公开信息。

`narration` 可以按需附带少量结构化旁路信息，例如提及的实体、明确承诺、玩家目标、未解决指代以及 `memory_candidates` 或 `event_candidates`。不存在相应内容时不得为填满字段而生成；除输出契约明确要求的字段外，旁路候选不构成每回合固定输出。已生成的内容与叙事一同可靠记录，供 Information AI 和异步 Memory 任务使用；它们必须引用当前回合来源，在经过解释和校验前不是权威事实。

## 校验与失败处理

所有 GM 结构化输出都必须经过 schema 和权限校验。

- 越权的信息请求应被拒绝，并只返回允许使用的最小信息；
- 非法状态变化不得执行；
- 叙事与已提交事实冲突时，保留权威状态并重新生成或纠正叙事；
- 提交后的叙事失败可以使用相同的 `turn_id` 和 `state_version` 重试；
- 提交前失败时保留待处理回合，不生成正式结果叙事；
- 结构化输出校验失败时不得执行其中的候选操作。

GM AI 的核心边界是：负责理解与表达，不负责决定事实；可以读取完成当前叙事所必需的秘密，但只能读取经过过滤后的最小范围。
