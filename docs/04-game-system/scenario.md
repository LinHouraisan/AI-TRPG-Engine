# 剧本系统

## 定位

Scenario Domain 保存不可变剧本定义与当前 `StoryProgress`；Scenario Runtime 确定性检查节点条件并提交进度；Director 只分析路径和提出适应性候选。系统不设置独立 Story AI。

## Scenario Canon

Canon 包含核心设定、关键事实、初始实体身份、节点定义、硬性因果约束和结局条件。原始内容不因游玩改写。作者预设、导入事实、用户确认与 AI 适应性内容必须保留不同来源标记。

## ScenarioNode

节点描述前置、触发、完成、失败、替代条件、相关实体、线索、秘密、可见结果和不可逆影响。节点表达必须发生或可能发生的事实条件，不把固定场景顺序当作唯一道路。

## StoryProgress

运行状态记录节点的锁定、可用、进行、完成、失败、休眠或被替代，以及当前采用的路径和结局方向。每次变化引用触发事件、条件评估和来源版本，只能由 Scenario Runtime 校验后提交。

## 标准推进

状态提交后，Scenario Runtime 检查受影响节点的结构化条件，并由确定性 Story Monitor 汇总节点变化、结构可达性、线索覆盖和推进停滞。只有这些结果仍存在语义或因果缺口时才触发 Director；Director 增量更新可重建的剧情前沿，并返回带来源、必要条件、有效场景和失效条件的适应机会。候选再经过 Canon、领域约束、可见性与节点条件检查，才可成为正式进度或内容扩展。

## 偏离与 fail-forward

玩家可以放弃目标、破坏关键资源或进入未预设路线。系统先寻找仍成立的原始节点，再寻找有因果来源的替代路径；必要时允许节点失败、剧情休眠、适应性节点或替代结局。失败保持其代价，不保证回到原定结局。

## 线索与秘密

线索的存在、获得、解释和关联可以分别建模。玩家未发现的答案、未来节点和幕后条件不进入 GM 的完整上下文；GM 只接收当前可表现机会和禁止泄露事项。

## 失败处理

Director 失败不改变 `StoryProgress`。条件冲突、来源不足或违反 Canon 的候选被拒绝。所有合理路线都失效时允许自然失败或结束，不以无来源巧合强行续接。
