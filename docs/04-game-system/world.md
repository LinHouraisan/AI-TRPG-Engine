# 世界系统

## 定位

World Domain 维护当前任务范围内需要精确追踪的世界时间、地点状态、全局条件和跨场景影响。它不以模拟所有地点和 NPC 的持续运行作为目标。

## 定义与状态

世界定义描述地点、连接、历法、阵营、基础环境和内容声明的稳定设定。世界状态描述当前时间、地点可达性、环境变化、已发生全局事件和正在生效的跨场景条件。场景细节归 Scene Domain；世界只保存需要跨场景持续的事实。

## 时间

时间由明确行动、规则消耗、场景推进或已提交事件推进。时间变化可以触发到期效果、计划、地点变化和剧情条件。程序处理明确计划与阈值；无法仅靠规则判断的社会或叙事影响可以交给 World Analyzer 提出候选。

## 跨场景影响

火灾、封锁、警报、天气、阵营行动等影响必须有来源、范围、开始时间、持续条件和受影响实体。Runtime 将候选分发到 Scene、NPC、Item 或 Scenario Domain 校验，并在需要时原子提交，World Domain 不越权修改其他领域。

## World AI 边界

可选 World Analyzer 根据已提交事件分析更广泛后果，例如消息传播、势力反应或地点长期变化。它不能让未获知事件的角色立即反应，不能无依据创建关键资源，也不能为了制造“活世界”而在后台任意改写状态。

## 可见性

真实世界状态、玩家已知地图、NPC 认知和 GM 可叙事视图相互分离。远处或秘密变化在被感知、调查或传播之前，不直接公开给玩家。

## 有界模拟

早期系统只精确推进与当前战役、已安排后果和相关实体有关的部分。非活跃区域可以在重新进入时依据经过的时间和已提交条件生成候选，但必须保留来源并通过校验，不能声称后台已经精确模拟全部细节。

## 失败处理

世界分析失败时保留已有状态和明确计划；跨领域候选部分不合法时不做部分提交；时间或分支版本冲突时重新评估。派生地图或索引损坏可重建，不影响权威世界状态。
