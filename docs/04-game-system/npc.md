# NPC 系统

## 定位

NPC Domain 维护正式 NPC 的定义、权威运行状态和领域约束。NPC 由 GM 面向玩家扮演；可选 NPC Analyzer 只分析动机或反应候选，不建立独立聊天角色或私有事实源。

## 定义与状态

`NPCDefinition` 描述来源身份、角色定位、基础特征、公开外观、初始知识和内容作者给出的目标。`NPCState` 描述当前地点、生死与伤势、情绪或立场、已知事实、关系、目标进度、承诺、计划和状态效果。临时表演细节不必全部结构化，但会影响后续因果的重要内容必须进入事件或状态。

## 知识与感知

NPC 只能依据自身已知事实、合理感知和收到的信息行动。知识条目应有来源、获得时间、可信度语义和可见范围；幕后真相与 NPC 相信的内容可以不同。GM 获得的是当前表演所需视图，不自动获得所有 NPC 秘密。

## 行动与反应

程序处理明确条件、规则效果和状态约束；Analyzer 可以基于目标、关系、知识和近期事件提出言行、计划或态度变化候选。候选不能预先决定检定结果，也不能赋予 NPC 未知信息。需要跨领域变化时，由 Runtime 分发给相应领域共同校验。

## 关系与承诺

关系变化必须引用具体互动或事件。承诺记录双方、内容、条件、状态与来源，不能只保留在对话摘要中。数值或标签是权威关系事实的表达方式之一，不应取代产生变化的事件。

## 生命周期

创建、加入场景、离开、失踪、死亡和复归均为显式状态变化。死亡等不可逆结果不能为了剧情方便被 AI 撤销；若规则或设定允许复归，必须通过新的有来源事件实现。

## 一致性与失败

- 同一 NPC 同一时刻的位置和状态必须满足领域约束。
- NPC 不得使用另一分支或不可见知识。
- GM 表演与状态冲突时纠正叙事，不修改状态迁就台词。
- Analyzer 失败时使用已有状态和确定性行为继续，必要时降低复杂度或请求澄清。
