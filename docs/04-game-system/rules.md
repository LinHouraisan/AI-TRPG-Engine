# 规则系统

## 定位

Rule Engine 根据 Rule Pack、权威状态和结构化行动执行确定性裁定。AI 可以理解玩家意图和解释结果，但不能选择对自己有利的规则、修改骰点或直接决定成功失败。

## Rule Pack

Rule Pack 描述属性与技能、检定、难度、修正、资源、伤害、状态效果、时间和冲突解决方式，并具有稳定标识与兼容版本。战役引用采用的规则版本；规则更新不能静默改变已有裁定的含义。

## 行动解析

玩家描述想做什么，GM 可输出受约束的行动意图。程序结合当前状态确定行动者、目标、适用规则和可选修正。若目标、方式或风险选择会显著改变结果，先请求澄清；玩家不必自行填写技能名或骰式。

## 裁定记录

规则裁定记录输入状态版本、采用规则、难度与修正来源、随机请求与结果、成功等级及效果候选。相同状态、输入、规则版本和随机种子应产生相同程序结果。

## RNG

RNG Service 独立生成并记录随机种子、表达式和结果。公开或秘密只影响展示范围，不影响可审计记录。失败重试和叙事重试不得重新掷骰。

## 效果与提交

Rule Engine 产生裁定与效果候选；各领域校验生命、资源、物品、位置或剧情条件变化；Runtime 统一原子提交。规则结果本身不能绕过领域不变量。

## 歧义与房规

规则包未覆盖或存在多种合理解释时，系统应采用已确认房规，或向玩家说明歧义并请求选择。临时裁定必须记录适用范围和来源，不能在后台无提示改变规则。

## 不支持的行动

自由行动不会因为不在建议列表中被拒绝。若当前内容缺少相应规则，可采用明确标注的通用裁定、纯叙事处理或说明能力限制；不得伪造精确规则。

## 失败处理

规则缺失、状态不完整、版本不兼容或随机记录失败时暂停需要裁定的操作。已经完成的裁定若尚未提交可以安全重试提交；已经提交则只重试展示。
