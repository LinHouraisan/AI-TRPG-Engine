# 道具系统

## 定位

Item Domain 管理道具定义、实例、位置、持有、容器、数量、耐久、充能和状态效果。道具变化由规则、玩家行动、时间或已提交事件产生，不能由叙事直接改写。

## 定义与实例

`ItemDefinition` 描述类型、公开描述、基础规则、可堆叠性、容量或使用约束。`ItemInstance` 表示战役中的具体对象或堆叠，拥有稳定 ID 与当前状态。相同模板的两个关键物品仍是不同实例。

## 所有权、位置与容器

道具在同一版本中应有明确位置语义：由实体持有、装备、位于场景、置于容器或已销毁。容器关系不能成环，容量和访问条件由领域约束检查。转移涉及来源与目标时必须原子更新，不能出现重复持有或凭空丢失。

## 数量与状态

消耗、拆分、合并、耐久、充能和效果变化记录前后值与原因事件。不可堆叠实例不以数量替代身份；关键物品即使耗尽或损毁，也保留历史可引用状态。

## 使用流程

玩家声明使用意图，程序读取物品、角色、场景和规则状态，Rule Engine 生成裁定，Item Domain 校验消耗与效果候选，Runtime 原子提交相关领域变化。GM 只叙述已提交的公开结果。

## 创建与销毁

内容初始化、制作、获得、生成和销毁必须有定义或事件来源。AI 可以提出符合世界与规则的物品候选，但不能无来源生成关键道具或把候选描述为已经存在。

## 可见性与失败

未知属性、隐藏夹层、诅咒和未鉴定效果可与公开视图分离。查询只返回当前主体允许知道的部分。转移冲突、数量不足、容器非法或版本过期时拒绝整个相关变化；索引错误时从权威状态重建。
