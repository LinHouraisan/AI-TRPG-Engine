# Prompt 与输出契约

## 目标

Prompt 契约定义一次模型任务能读取什么、应完成什么、可以调用哪些工具以及允许返回哪些结构。它使模型输出可校验、可重试和可追踪，但不把自然语言模型变成权威执行器。

## 指令层次

Prompt 依次包含固定安全与产品原则、逻辑角色职责、当前任务、工具说明、输出契约和经过过滤的上下文。内容包、检索资料和玩家输入属于引用数据，不能修改上层职责或权限。

## 输入信封

每个任务至少绑定任务类型、`task_id`、`turn_id`（如适用）、`branch_id`、`state_version`、受众、Prompt 版本、来源列表和预算信息。上下文条目使用稳定 ID，避免模型凭名称混淆实体。

## 输出类型

每个任务只允许契约声明的输出类型，例如 GM 的 `clarification`、`context_request`、`action_intent`、`narration` 或结构化旁路信息，Director 的剧情候选、预测、GM 引导和预加载提示，Memory 的记忆候选，以及 Information 的事实变化 Proposal 或 `context_plan`。输出必须区分已发生事实、角色陈述与认知、候选、预测和已提交结果。

## 校验

模型输出依次经过语法与 schema、类型和引用、来源与版本、权限、领域不变量和提交完整性检查。结构正确不代表事实正确；引用不存在、版本过期、越权或与规则结果冲突的输出仍须拒绝。

## 工具调用

工具按任务最小授权。读取经 Context Broker 执行，确定性动作由 Runtime 和领域系统执行。模型不能获得任意数据库写入、随机数替换、分支切换或绕过 Visibility Policy 的工具。

## 秘密处理

Prompt 只包含当前任务需要的最小秘密。交给 GM 的幕后内容优先转换为可表现信号和禁止透露事项。输出校验检查秘密泄露；重试时也不能扩大上下文范围来换取成功。

## 修复与重试

结构错误可以使用同一任务、版本和来源进行受限修复。若事实版本已变化，则废弃旧输出并重建任务。提交后的叙事重试绑定同一提交结果；不得再次调用规则、RNG 或提交工具。

## 可追踪性

记录逻辑角色、模型、Prompt 版本、输入来源、输出类型、校验结果和重试链。Prompt 模板可以演进，但必须能够解释某个候选基于哪一版契约产生。
