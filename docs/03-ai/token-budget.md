# Token 预算

## 定位

Token 预算控制一次模型任务的输入与输出规模。它与 Active Context Store 的工作集容量不同：Store 可以保留比单次 Prompt 更多的材料，Prompt 只选择当前任务需要的部分。

## 预算组成

每次任务先为固定指令、角色职责、输出契约、工具定义、玩家输入、必需状态和预期输出预留空间。剩余预算才分配给场景实体、近期事件、长期记忆、关系、剧本材料和可选叙事连续性。

## 优先级

一般保留顺序为：

1. 安全、权限和输出契约；
2. 当前行动必需的权威状态与已提交结果；
3. 玩家输入、行动者、目标和适用规则；
4. 当前场景与直接交互实体；
5. 当前任务依赖的剧情或领域约束；
6. 近期关键事件和有来源的长期记忆；
7. 关系扩展与叙事连续性；
8. 推测性预取和低相关背景。

不同任务可以调整中间层次，但不能移除权限、版本、必需状态或输出空间。

## 降级策略

预算不足时依次移除未使用预取、降低关系扩展、以引用替代完整材料、选择更短的有来源摘要，并减少可选风格示例。不能截断结构化对象造成歧义，也不能用摘要覆盖当前权威状态。

若最低必需输入与输出仍无法容纳，系统应拆分任务、请求更大能力的模型或暂停并报告，不应继续发送已知不完整的关键状态。

## 输出预算

输出空间在选择可选上下文之前预留。叙事、结构化候选和工具调用可以采用不同预留策略。模型因长度中断的结构化输出视为无效，不执行其中的部分变化。

## 动态调整

预算按任务类型、模型能力、当前场景复杂度和用户配置决定，不设所有模型通用的固定数值。调整依据包括缺失信息率、补查次数、截断率、校验失败、平均输入输出 Token、延迟、成本和叙事事实冲突率。

## 成本与质量边界

成本优化优先减少重复和低相关材料，不能牺牲权威状态、秘密边界或可复现裁定。后台摘要可以延后或批处理；玩家前台任务应优先保证正确性和可恢复响应。
