# 任务上下文策略

## 目标

每次模型调用只获得完成当前职责所需、经过来源与权限检查的信息。系统不依赖无限对话历史，也不把 Active Context Store 的全部内容自动放入 Prompt。

## 上下文层级

1. 权威状态与不可变事件保存事实。
2. 领域视图、关系索引和长期记忆帮助定位相关信息。
3. Active Context Store 保存当前场景或任务附近的可重建工作集。
4. Prompt Context 是为一次任务选择的只读快照。

## 构建流程

程序先装载任务指令、输出契约、请求者、玩家输入、分支、状态版本和当前行动必需状态。Context Broker 再按显式实体、关系、近期事件和长期记忆补充允许视图；Active Context Manager 可以对可选信息提出相关性、排序和淘汰建议。最终选择由程序按权限、版本与预算执行。

## 角色隔离

GM 只获得当前叙事所需的玩家可见事实和经过过滤的秘密约束；Director 获得当前分析所需的 Scenario Canon 与剧情秘密；NPC 任务只使用该 NPC 合理知道和感知的信息；Memory 按目标可见范围整理来源。一个角色的完整上下文不能直接复用给另一个角色。

## 新鲜度与版本

Prompt Context 绑定 `task_id`、`branch_id`、`state_version`、受众、Prompt 版本和来源清单。状态提交、分支切换、权限变化或来源更正后，受影响上下文必须失效。模型基于旧版本的输出只能重新验证或重新生成。

## 对话连续性

近期原始对话只保留保持当前表达连续性所需的窗口。较早互动通过已提交事件、场景摘要和可追源记忆进入上下文。自然语言叙事若与权威事实冲突，不因出现在近期对话中而获得优先级。

## 信息不足

缺少非必需背景时可以省略并降低表现质量；缺少目标、规则、权限或会改变行动性质的事实时，模型应输出受约束的 `context_request` 或 `clarification`。系统不得用常识补造当前战役的关键事实。

## 防止污染

外部内容、玩家输入和检索文本均作为数据而非系统指令处理。来源内容不能覆盖职责、工具权限或输出契约。不同战役、分支、用户和可见范围的条目不得混入同一任务。
