# 模型策略

## 目标

模型策略将 GM、Director、Memory、Active Context Manager 和领域 Analyzer 等逻辑职责与具体模型解耦。模型是可替换执行能力，不是战役状态的一部分。

## 能力登记

Model Capability Registry 记录可用模型在上下文长度、结构化输出、工具调用、语言质量、延迟、成本、隐私和本地运行等方面的已验证能力。供应商声明只能作为初始信息，职责匹配应以实际测试结果为准。

## 按任务选择

模型选择针对一次任务，而不是给整个战役永久绑定一个模型。选择依据包括任务类型、所需秘密范围、结构化可靠性、上下文规模、响应时限和用户配置。多个逻辑职责可以共享模型，同一职责也可针对意图理解、叙事或后台整理使用不同能力档位。

## 适配边界

Model Gateway 统一消息、工具、结构化输出、超时、重试和用量记录。业务层只依赖任务契约，不直接依赖供应商格式。BYOK 凭据由专门适配层保存和使用，不进入 Prompt、事件日志、存档或普通诊断输出。

## 回退

回退模型必须满足当前任务的最低能力与隐私要求。结构化任务不能回退到无法可靠遵守输出契约的模型；秘密任务不能回退到不允许处理该数据的位置。回退可以降低叙事质量或延后后台任务，但不能放宽权限、跳过校验或改变已提交事实。

## 模型替换

更换模型不会迁移战役事实。系统重新验证对应职责的结构化输出、工具能力和目标语言质量，并保留 Prompt 版本与模型能力记录以便诊断。模型差异造成的叙事风格变化不能反向修改状态。

## 可观测性与隐私

记录任务类型、模型标识、Prompt 版本、Token、延迟、重试、校验结果和错误类别，但默认不长期保存完整秘密上下文。诊断数据遵循与游戏数据相同或更严格的权限边界。

## 失败原则

- 前台任务失败时提供安全重试或恢复提示。
- 后台任务失败通常排队重试，不阻塞回合。
- 达不到最低能力时明确拒绝任务，不假装成功。
- 模型输出始终视为不可信候选，供应商或模型等级不改变这一边界。
