# 产品路线图：单人跑团与数据标注

更新日期：2026-09-29。状态：目标范围，不能据此认定功能已经实现。
架构与验收以 [V1.0 架构手册](../ARCHITECTURE-V1.md) 为入口；实现证据见 [当前状态](../CURRENT-STATUS.md)。

## 1. V1.0 的最终交付

AI TRPG Engine V1.0 是以 Python 为业务核心、Electron 为桌面界面的本地应用，提供：

- 玩家独立开始、持续游玩、保存、恢复并完成单人战役。

- 面向本项目运行数据的标注、修订、复核、数据集管理与导出。

- 可独立安装的 Windows x64 版本、模型配置和玩家/标注操作文档。

迁移完成、某个模块完成或合成演示完成，都只是阶段结果。只有游戏、数据标注和分发验收共同通过，才交付完整 V1.0。

## 2. 已确认的范围调整

### 移除作者产品需求

V1.0 不交付内容作者工作台、可视化模组编辑器、作者 CLI 产品、创作教学、发布渠道或内容市场。“作者能够制作、试玩和发布正式包”不再是验收条件。

保留玩家读取、导入、校验和使用已有内容。既有内容校验/打包脚本若仍用于内部维护与回归测试则保留，不因范围调整自动删除。

### 纳入数据标注

数据工作台覆盖本项目产生的玩家对话、模型回复与 Agent 任务证据，首版按本地单使用者设计：

- 问题、优质、中性及执行失败样本采集和去重。

- 问题标签、事实/规则/行动承接/叙事四维评分、人工理想回复和成对偏好选择。

- 草稿、提交、复核、退回、修订历史；自复核明确标记。

- 数据用途资格、训练/测试分组隔离、版本冻结、脱敏与质量报告。

- 可追溯的评测、SFT、偏好数据导出及旧 audit-case-v1 适配。

标注修改不写回真实战役；人工修订不是新发生的游戏事实。机器诊断只提供建议，不能自动批准训练数据。

## 3. 保留的玩家承诺

- GM 是唯一游戏前台，同时支持建议行动和自由输入。

- AI 提议、程序校验与提交；规则结果、事实和重要记忆有来源。

- 已声明支持的文字卡、轻量冒险和正式包可按实际能力使用。

- 角色、场景、物品、关系、线索和剧情状态可持续保存。

- 保存、重启恢复、回滚、分支与失败处理不会静默损坏历史。

- 合格模型可以替换，战役存档不依赖某个模型。

- 正式运行链和评测使用同一应用能力，不维护平行的评测产品。

## 4. 非目标

- 多人实时联机、真人 GM 工作台、大量自主 NPC 社会模拟。

- 所有规则、卡片变体和模型的完全兼容。

- 通用外部数据标注、多媒体标注、多人组织与任务分发平台。

- 应用内自动训练、自动发布模型或任意代码插件。

- 面向内容作者的制作、编辑和分发产品。

## 5. 交付里程碑

| 阶段 | 实际交付结果 | 退出条件 |
| --- | --- | --- |
| M0：范围与合同 | 统一架构、游戏与标注数据合同、来源和版本规则 | 当前目标一致，历史冲突已标记，关键合同有明确消费者 |
| M1：Python 游戏核心 | 后端接管规则、回合、状态、GM、恢复；桌面成为客户端 | 内置短剧本可完成，规则对照、重复请求、版本冲突和恢复验证通过 |
| M2：标注完整流程 | 样本池、标注修订、复核、数据集冻结、质量报告和导出 | 四类来源可处理；用途、脱敏、版本和泄漏规则通过正反例验证 |
| M3：完整体验与效果 | 玩家内容导入、长期运行、认证模型与数据集驱动评测 | 内容按支持矩阵可用；长会话和真实模型证据齐备 |
| M4：正式 V1.0 | Windows 安装与升级产物、玩家/标注文档、支持矩阵 | 干净环境验收、外部使用反馈和发布门槛通过 |

每个阶段按完整使用流程推进，不以空目录、组件数量或模型数量作为进展。旧实现随能力迁移逐项退出，避免旧桌面与新后端长期重复开发。

## 6. 验收口径

- 具体完成条件采用架构手册第 11 节 G1–G7、D1–D6、R1–R3。

- 长会话工程下限为 100 个已提交回合、至少 3 次关闭恢复，并验证 10k 事件重放；真实模型叙事和记忆另行评价。

- 冻结数据集之后的标注修改不得改变历史导出。

- 模型效果、人工标注质量、软件合同测试分别报告。

- 问题池不能推导全局错误率；机器生成样例不能充当真人反馈和人工标注成果。

- 正式发布记录硬件、模型、内容版本、数据集版本和实际支持边界。

## 7. 后续范围变更

新需求先判断属于游戏、标注、基础设施还是版本之外，再更新对应合同和验收。不得通过“重构”静默增加作者、多人平台或自动训练范围。

本文件替代此前含作者交付要求的路线图。历史实现细节可查 Git 历史与已标为历史参考的旧方案。
