# Obsidian RAG 与 AI TRPG 领域模型训练设计

## 1. 背景与目标

本设计在两个现有项目中补齐可复现的模型训练与评测证据：

- `个人知识库`：训练一个面向 Obsidian RAG 的结构化查询规划 LoRA Adapter，降低 Agent 工具选择和参数生成的不确定性。
- `AI TRPG Enginee`：在现有主持人文风 LoRA 流程之外，增加一个面向模组知识检索的领域 Embedding 微调实验。
- 两个生成任务共享 `Qwen2.5-3B-Instruct` 基座，但使用互相独立的 Adapter；Embedding 使用独立的双塔编码模型。

交付目标不是宣称训练后必然提升，而是形成“数据构建、训练、推理、基座对比、失败回退、报告留档”的真实闭环。所有简历指标必须来自实际运行生成的报告。

## 2. 范围与非目标

### 范围

1. Obsidian 查询规划 LoRA：训练、结构化输出校验、离线评测和可选接入。
2. TRPG Embedding 微调：训练样本构建、对比学习、离线检索评测和 OpenAI-compatible 推理服务。
3. TRPG 文风 LoRA：复用现有 `tools/lora`，补齐正式数据、训练运行和 base/RAG/LoRA 对比报告。
4. 云端训练使用一张 24GB 显存 GPU，三个任务串行执行。

### 非目标

- 不训练新的基础模型，不做全参数微调。
- 不让 Obsidian Agent 创建、修改、移动或删除笔记。
- 不把风格 LoRA 描述为逻辑推理或事实记忆增强。
- 不将 Embedding 对比学习误写为 LoRA。
- 不在仓库提交 API Key、基础模型、Adapter、优化器状态或其他大文件。
- 不为了训练改造桌面应用主流程；所有新模型都必须可选并保留现有模型回退。

## 3. 总体架构

| 子任务 | 基座 | 训练方式 | 主要产物 | 核心指标 |
| --- | --- | --- | --- | --- |
| Obsidian 查询规划 | Qwen2.5-3B-Instruct | PEFT LoRA SFT | 查询规划 Adapter | Schema 合法率、意图准确率、Recall@3、回退率 |
| TRPG 领域检索 | BAAI/bge-small-zh-v1.5 | 对比学习 | SentenceTransformer 模型 | Recall@3、MRR、nDCG@3 |
| TRPG 主持人文风 | Qwen2.5-3B-Instruct | PEFT LoRA SFT | 文风 Adapter | 格式遵循率、非法代掷率、事实冲突率、人工盲评 |

云端先缓存两个基座模型，然后按“TRPG Embedding → TRPG 文风 LoRA → Obsidian 查询规划 LoRA”顺序训练。每个任务独立保存配置、数据摘要、日志、Adapter 或模型目录以及机器可读评测报告。

## 4. Obsidian 查询规划 LoRA

### 4.1 职责边界

LoRA 只负责把用户请求转换为一个受限的首步查询计划，不直接读取文件，也不负责最终回答。计划结构固定为：

```json
{
  "intent": "search_notes",
  "query": "LangChain 工具调用的确定性保障",
  "top_k": 3
}
```

允许的 `intent` 只有：

- `search_notes`：检索知识问题。
- `open_note`：定位并打开用户明确指定的笔记。
- `find_related_notes`：查找指定主题或笔记的关联内容。

`query` 必须是非空文本，`top_k` 限制在 1–5。规划结果先经 Pydantic 校验，再由现有只读知识服务执行。非法 JSON、未知意图或非法参数一律记录并回退到现有普通检索流程，不把模型字符串直接当作函数或路径执行。

### 4.2 数据构建

训练数据从 `sample_vault` 的标题、标签、链接和正文主题派生，结合人工模板生成搜索、打开和关联查询。数据集中同时包含：

- 直接问答和模糊搜索表达。
- 明确要求打开某篇笔记的表达。
- 查询相关笔记、反向链接和同标签内容的表达。
- 越权要求修改或删除笔记的负例；其目标仍为安全的只读搜索，而不是写操作。

目标规模为 600–1000 条。按笔记或主题分组切分训练集、验证集和测试集，避免同一笔记的近似改写同时进入训练和测试。自动生成后进行重复检测、Schema 校验，并人工抽检至少 10%。

### 4.3 训练与评测

训练采用与 TRPG 文风任务一致的 Qwen2.5-3B 基座和 LLaMA-Factory/PEFT 工具链，但写入独立 Adapter 目录。评测固定比较同一测试集上的 base 与 LoRA：

- Schema 合法率：输出能否被目标 Pydantic 模型解析。
- 意图准确率：`intent` 是否匹配标注。
- 参数约束通过率：`query` 和 `top_k` 是否满足约束。
- Recall@3：执行规划后的检索结果是否命中目标笔记。
- 回退率：多少请求因输出无效而退回普通 RAG。

只有实际生成的 JSON/Markdown 报告可以提供简历数字。

## 5. TRPG Embedding 领域微调

### 5.1 数据结构

从 `electron/content/packs` 中抽取房间、NPC、物品、事实、调查线索、门锁和状态条件，标准化为可检索文档。每个训练样本包含：

```json
{
  "query": "码头失踪案里谁最后见过管理员？",
  "positive": "对应人物或事实条目",
  "negative": "语义接近但不能回答该问题的条目"
}
```

正样本由字段信息和人工模板生成；困难负样本从基座模型检索结果中选取排名靠前但 ID 不匹配的条目。数据按内容包或实体分组切分，禁止把同一实体的近似描述泄漏到测试集。

### 5.2 训练与服务

使用 `sentence-transformers` 对 `BAAI/bge-small-zh-v1.5` 进行轻量对比学习。它与当前默认的 `bge-m3` 是独立实验；评测只比较同一基座微调前后，不用不同大小模型的差异冒充训练收益。

训练产物通过一个最小 OpenAI-compatible `/v1/embeddings` 服务暴露。现有 Electron 和 FastAPI AI 服务继续通过 `base_url + model` 选择 Embedding；服务不可用时回退到现有配置，不改变 JSON 向量索引的可替换边界。

### 5.3 评测

在固定测试查询集上输出：

- Recall@3：正确条目是否出现在前三名。
- MRR：首个正确结果的倒数排名。
- nDCG@3：前三名排序质量。
- 平均单查询编码延迟，仅作为环境记录，不跨硬件比较。

评测报告同时记录模型名、数据集哈希、随机种子、训练配置和样本数量，保证结果可追溯。

## 6. TRPG 主持人文风 LoRA

### 6.1 复用范围

现有 `tools/lora` 已具备 20 条人工种子、数据扩展脚本、Qwen2.5-3B LoRA 配置、AutoDL 单卡脚本、Adapter 合并脚本，以及 base/RAG/LoRA 评测入口。本次不重写该链路，只补齐正式实验：

1. 基于现有模组生成 400–800 条候选样本。
2. 去重、格式校验并人工抽检至少 10%。
3. 运行 LoRA 训练并保留 Adapter、日志和配置副本。
4. 在同一评测集上运行 base、RAG、LoRA 三档评测。

### 6.2 训练目标

文风 Adapter 只优化以下行为：

- 第二人称、冷峻克制的主持人口吻。
- 回复中包含可行动的新信息。
- 必要时提示检定，但不编造骰点或判定结果。
- 以明确行动钩子收尾。
- 不与提供的场景事实冲突。

评测同时包含规则和事实一致性检查，避免只看“像不像某种文风”。

## 7. 失败处理与安全约束

- 数据生成接口失败时按批次重试并保留已通过校验的样本；单批失败不覆盖已有数据。
- 训练中断后依靠 LLaMA-Factory checkpoint 恢复，不提交 checkpoint 到 Git。
- 推理服务超时或模型不可用时使用现有基座/远端模型，不阻断主应用。
- Obsidian 规划输出永远先校验后执行，工具仍保持只读。
- 所有凭证只从环境变量或云平台密钥管理读取；此前暴露的 DeepSeek Key 必须作废，不能进入数据、日志或仓库。
- 自动生成样本必须标明生成来源；人工抽检比例和剔除规则写入数据报告。

## 8. 文件边界

### `AI TRPG Enginee`

- 保留并小幅补强 `tools/lora/`，不重写现有文风训练链路。
- 新增 `tools/embedding/`，容纳数据构建、训练、评测和最小推理服务。
- 评测结果写入 `docs/bench/`；权重、Adapter、缓存和云端输出加入忽略规则。
- 仅在需要选择微调 Embedding 服务时修改现有配置，不改动无关 Electron 业务代码。

### `个人知识库`

- 新增 `training/query_planner/`，容纳数据构建、LLaMA-Factory 配置和离线评测。
- 在 `app` 中增加严格的规划结果模型和可选规划器入口；关闭该配置时保持当前 Agent 行为。
- 测试覆盖 Schema 校验、白名单分派、非法输出回退和只读约束。

## 9. 最小验收标准

三个实验分别满足以下条件才算完成：

1. 固定命令可以从数据构建运行到训练或 smoke train。
2. 生成独立、可加载的 Adapter 或 Embedding 模型产物。
3. 使用固定测试集生成 base 与 tuned 的机器可读对比报告。
4. 推理接入失败时能够回退，不破坏现有应用。
5. README 明确训练数据来源、硬件环境、方法边界和实际结果。
6. 简历只采用已跑出的指标；如果结果没有提升，如实记录并分析，不改写数字。

## 10. 今晚执行顺序

1. 本地完成三个任务的数据、配置、评测和 smoke test。
2. 云端先运行 TRPG Embedding，快速获得第一组检索指标。
3. 运行已有 TRPG 文风 LoRA，并完成 base/RAG/LoRA 对比。
4. 运行 Obsidian 查询规划 LoRA，并生成结构化指标报告。
5. 下载 Adapter、Embedding 模型和日志后关闭云主机；最后再根据真实报告更新简历。
