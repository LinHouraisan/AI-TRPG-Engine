# 《雾港末班车》公开演示版设计

Status: Accepted by product owner in chat on 2026-08-23

## 1. 目标

在现有 AI TRPG Engine Demo/Electron 程序上完成一个可公开演示的纵向版本。陌生用户应能配置 DeepSeek、导入或选择调查员、创建《雾港末班车》战役、使用建议行动或自然语言游玩、保存与恢复，并在约 2.5–3.5 小时内完成至少一个正式结局。

本阶段只使用 DeepSeek 开放平台作为云模型来源。规则、随机数、权威状态、事件提交、剧情条件和恢复逻辑仍由程序负责。

## 2. 范围

本阶段完成以下五项：

1. 接通桌面版复杂自由行动的单一 GM 工具闭环；
2. 制作三小时原创短剧本《雾港末班车》；
3. 打通角色导入、创建战役、游玩、结局、关闭和继续的完整 UI 流程；
4. 完善 DeepSeek 真实连接、错误诊断、费用记录和关键真实测试；
5. 增加自动、测试和手动检查点，以及可查看测试用例的一键复制恢复。

不在本阶段实现：其他云 Provider、通用可视化作者工具、完整通用 Rule Pack、自动更新、多人或真人 GM 工作台、完整 V1.0 内容生态。

## 3. 剧本设计

### 3.1 定位

《雾港末班车》是单人调查惊悚短剧本，目标时长 2.5–3.5 小时。它使用现有调查员、技能、物品、线索、场景、NPC、剧情节点和条件系统，只补充该剧本确实需要的领域动作。

### 3.2 四幕结构

1. **雾港车站**：玩家受托寻找失踪档案员，在末班车发车前调查站台、行李房和售票室，认识列车员、记者和身份可疑的乘客。
2. **消失的乘客**：列车开出后，一名乘客从所有人的记忆和名单中消失。玩家比对车票、照片、行李与 NPC 证词。
3. **不存在的终点**：列车进入地图上不存在的旧线路。玩家可以调查车厢、潜入驾驶室、组织乘客、与列车员合作或对抗。
4. **最后的选择**：玩家确认列车正在用乘客的记忆维持一座已经消失的车站，并选择救回失踪者、让列车完成循环、破坏线路或接受幕后交易。

### 3.3 内容规模与可达性

- 7–9 个可探索场景；
- 5 个主要 NPC；
- 12–16 件关键道具；
- 15–20 条线索；
- 3 条主要调查路径；
- 至少 3 个正式结局；
- 1 条只能通过合理自由行动触发的隐藏路线；
- 每个关键结论至少有两条独立可达线索；
- 关键路径被破坏时，Story Monitor 必须能识别缺口并启用作者定义的替代入口。

人物秘密、线索关系、规则结果和结局条件由 Scenario Pack 与程序控制。DeepSeek 可以塑造 NPC 表达和叙述，但不能改写谜底或把候选变化直接写成事实。

## 4. AI 回合闭环

### 4.1 默认模型

所有确实需要模型的任务默认路由到 DeepSeek Flash。确定性查询、规则计算、已有结构化 Memory 差异和 Story Monitor 不因“统一模型”而改成付费调用。

### 4.2 数据流

```text
玩家输入
  → 确定性快速路由
  → 无法确认时进入单一 DeepSeek GM 任务
  → GM 输出意图、目标、行动方式、工具请求或澄清问题
  → 程序选择规则并生成可复现随机结果
  → Validator 检查引用、权限、版本和领域不变量
  → SQLite 原子提交事件、裁定与状态
  → 同一 GM 任务根据已提交公开结果生成正式叙述
```

### 4.3 路由规则

- 移动、查看背包、观察唯一明确目标等操作继续使用确定性快路由；
- 纯角色扮演、NPC 对话和复杂自由行动使用 DeepSeek；
- 有重大风险、复合目标或关键歧义时只生成澄清，不执行规则、不掷骰、不提交状态；
- GM 只能提出行动者、目标、方式、玩家明确接受的风险和工具请求；
- GM 不能提交成功失败、骰点、伤害、道具转移、NPC 状态、剧情节点或任意数据库写入；
- 模型输出必须通过 JSON Schema、实体引用、Visibility、branchId 和 stateVersion 检查；
- 提交后的叙述失败只重试同一提交结果，不重新路由、掷骰或提交。

### 4.4 后台职责

- Information 优先执行确定性查询，仅在无法可靠消歧时调用 DeepSeek；
- Memory 在场景结束、近期窗口即将淘汰或积压达到阈值时整理，不阻塞当前回合；
- Director 只在关键剧情状态改变、作者路径受阻或长期停滞时运行；
- 后台任务失败保留待处理状态，不撤销玩家已经提交的回合。

## 5. DeepSeek Provider 与费用

### 5.1 连接验证

连接测试按顺序检查：

1. HTTPS 与认证；
2. 配置模型是否存在；
3. 最小文本生成；
4. JSON 结构化输出；
5. 禁用思考模式参数是否被服务接受。

UI 必须分别解释无效密钥、余额不足、限流、模型不存在、网络超时、服务端错误和响应契约错误。错误响应不能包含密钥、完整 Prompt、用户目录或内部 stack。

### 5.2 预算

- 开发期真实调用预算上限约 4 元人民币；
- 保留约 1 元用于最终全流程验收；
- 自动化测试优先使用固定假模型；
- 真实 DeepSeek 仅用于 Provider 契约、关键自由行动样例、NPC 对话样例和完整流程验收；
- 同一失败输入只执行明确上限内的重试；
- 接近预留线或服务返回余额不足时停止真实测试并保留未执行列表。

### 5.3 调用台账

每次真实调用记录任务类型、模型 ID、输入与输出 Token、缓存命中、耗时、重试次数、结果类别和估算费用。API Key 不进入 Renderer、SQLite 战役、普通日志、测试 fixture、导出或 Git。

UI 显示本次会话与累计开发测试消耗，并允许暂停新的云调用。

## 6. 玩家产品流程

```text
首次启动
→ DeepSeek 配置与真实连接检查
→ 导入或使用预设调查员
→ 选择《雾港末班车》
→ 创建全新战役
→ 开场说明
→ 游玩与自动保存
→ 检查点或恢复
→ 到达结局
→ 查看战役总结
```

首次使用界面必须让用户知道当前内容能力、云端数据边界、模型连接状态和下一步操作。任何失败都应保持已提交战役可继续或可恢复。

## 7. 检查点、备份与一键恢复

### 7.1 三类检查点

- **自动检查点**：每幕开始、关键剧情提交后和结局前创建；
- **测试检查点**：开发调试时创建，带测试名称、输入步骤、预期结果、实际结果和状态哈希；
- **手动检查点**：玩家随时创建并命名。

### 7.2 恢复语义

“复制并恢复”从检查点创建新分支，不覆盖来源分支，不删除检查点后的历史。新分支绑定检查点记录的 Scenario Pack、状态版本和内容版本。恢复前验证哈希；失败时停止并报告，不猜测修复状态。

### 7.3 测试与恢复页面

页面展示：

- 检查点名称、类型和创建时间；
- 所属幕、场景、分支和状态版本；
- 测试目的与输入步骤；
- 预期事件、状态和结局；
- 实际结果及通过/失败；
- 状态哈希；
- “复制并恢复”操作。

测试检查点作为可导入的开发测试存档随 Demo 交付。最终验收必须使用全新战役，不复用测试分支。

## 8. 开发过程备份

Git 里程碑按以下顺序保存，每个提交只包含对应阶段能够独立验证的改动：

1. DeepSeek 全职责路由、连接诊断与费用台账；
2. 自由行动单一 GM 工具闭环；
3. 《雾港末班车》完整 Scenario Pack；
4. 首次使用和完整游玩流程；
5. 检查点、复制恢复和测试查看器；
6. 最终 E2E、安装包、测试存档和已知问题。

已有用户改动不得混入里程碑。每个里程碑保留对应测试和验证命令。

## 9. 测试设计

### 9.1 自动化测试

- 固定假模型的 GM 工具调用契约；
- 简单、复杂、模糊、复合和恶意自由行动；
- 模型不能伪造骰点、状态变化或隐藏信息；
- NPC 对未公开秘密的可见性；
- 每个关键结论的双线索可达性与三个结局可达性；
- 401、余额不足、429、超时、5xx、错误 JSON 和断流；
- 提交前、提交中、提交后故障与叙述重试；
- 自动、测试和手动检查点；
- 恢复分支隔离、来源历史不变和重放哈希一致；
- DeepSeek 调用台账不包含密钥和完整秘密 Prompt。

### 9.2 真实 Provider 测试

- 模型列表与配置模型存在；
- 最小文本生成；
- 结构化 JSON 输出；
- 一个复杂自由行动工具闭环；
- 一段 NPC 对话；
- 一次提交后叙述；
- 一个完整短路径结局。

### 9.3 Windows E2E

- 干净用户状态安装与首次启动；
- DeepSeek 配置与错误提示；
- 导入角色并创建战役；
- 完成至少一个结局；
- 从结局前检查点复制恢复并完成不同结局；
- 关闭应用后继续战役；
- 模型失败不损坏已提交状态；
- 安装包覆盖安装后旧战役和加密密钥仍可用。

## 10. 公开演示退出条件

必须同时满足：

- 新用户不需要开发者介入即可开始并完成一个结局；
- 至少一次自由行动真实改变过程，而非仅改变措辞；
- 三个正式结局和隐藏路线通过可达性测试；
- 模型失败、应用关闭和叙述重试不损坏存档；
- 测试检查点可以一键复制恢复并展示对应测试用例；
- 固定测试路径重放得到相同状态哈希；
- DeepSeek 真实连接、结构化输出和完整短路径通过；
- Windows 安装包在覆盖安装后正常启动；
- 已知问题、模型费用和云端数据边界在 UI 或随附文档中明确说明。
