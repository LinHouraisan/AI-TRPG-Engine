# 关系与链接

## 两类关系

权威关系事实属于实体状态或已提交事件，例如持有、位于、认识、敌对、承诺和知晓。Relationship / Link Index 是从这些来源建立的查询索引，用于发现关联对象，不是独立事实源。

## 关系表达

关系应包含稳定的主体与客体 ID、关系类型、方向、来源、适用分支、有效版本或时间范围及可见性。对称关系也应由领域定义其对称语义，不能只因显示文本相似就推断。

不同关系由对应领域拥有约束：持有与容器归 Item Domain，位置归相应实体与 Scene 或 World Domain，NPC 社会关系与知识归 NPC Domain，剧情依赖归 Scenario Domain。索引只聚合引用，不接管约束。

## 时间变化

关系的建立、加强、减弱、终止和被发现均通过事件产生。当前状态保存有效关系，事件保留历史。摘要性的“信任度”或语义标签若由 AI 提出，必须引用具体互动并经过领域校验。

## 查询与遍历

Context Broker 可以按明确关系做有限扩展，例如场景中的实体、物品持有链和节点依赖线索。遍历必须限制关系类型、深度、数量、分支和可见范围，避免把整个关系网络装入任务上下文。

## 可见性

关系存在本身也可能是秘密。玩家观察到的态度、NPC 私有认知和幕后真实关系可以是不同视图；查询拒绝不能泄露隐藏关系是否存在。

## 重建与失效

状态提交、关系事件、更正、分支切换和权限变化会使相关索引条目失效。索引丢失时可从权威状态和事件重建。索引与来源冲突时拒绝使用旧条目，不反向覆盖来源。
