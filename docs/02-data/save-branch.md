# 保存、重放、回滚与分支

## 目标

保存系统使战役能够恢复、验证和派生新时间线。存档不是对话文本副本，也不绑定当时使用的具体模型。

## 保存内容

检查点记录战役、分支、事件位置、状态版本、状态哈希、内容包与 Rule Pack 引用以及必要的兼容信息。快照可以附带当前状态以加速恢复；事件日志仍保存检查点前后的因果历史。派生索引、长期摘要和 Active Context 可以保存为缓存，但必须允许重建。

## 恢复与重放

恢复先验证战役、分支、内容和规则兼容性，再载入可信快照并重放后续事件。每一步检查前置版本和状态哈希。校验失败时尝试更早的有效检查点；仍无法恢复则停止并报告具体缺口，不用 GM 叙事补齐状态。

## 回滚

回滚不会删除未来历史。系统从选定检查点创建或激活一条新分支，原分支保留为可查看的时间线。未提交的当前回合可以取消；已经提交的回合只能通过分支或显式更正处理。

## 分支

每个分支记录稳定 ID、父分支、分叉事件位置、创建原因和当前头版本。分支继承分叉点之前的历史，之后拥有独立事件序列、状态、记忆和派生视图。不同分支的上下文、任务和候选不得混用。

## 更正

若事实因系统错误需要修复，可提交带授权和原因的更正事件，或从错误前建立新分支。更正应指出受影响事件和新状态，保留审计链。普通玩家行动造成的不利结果不属于系统错误，不能用静默更正撤销。

## 可移植性

存档引用内容和规则的稳定标识及兼容版本，而不包含模型实例为权威组成。更换模型只要满足对应职责能力，不应改变已有事实。内容或规则无法兼容时应阻止继续或执行显式迁移，不能静默采用新语义。

## 失败处理

- 写入失败：旧检查点保持有效，不留下半份新存档。
- 快照损坏：从更早快照与事件重建。
- 事件缺失或哈希不符：停止恢复并报告损坏范围。
- 分支来源不存在：拒绝载入。
- 派生数据损坏：丢弃并重建，不影响权威历史。
