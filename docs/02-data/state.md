# 权威状态

## 定位

State Store 保存某一战役分支当前已经提交的结构化事实。Event Log 保存这些事实如何形成。二者共同构成权威数据：状态服务快速读取当前局面，事件支持追溯和重建。

## 状态组成

状态按领域组织实体状态、世界时间、场景状态、角色与 NPC 状态、道具实例、关系事实和 `StoryProgress`。逻辑分区不表示必须使用不同数据库；所有相互依赖变化仍受统一提交边界保护。

## 读取视图

State Store 提供绑定 `branch_id` 与 `state_version` 的只读快照。领域投影、搜索索引、关系索引、长期记忆和 Active Context 都从权威数据派生。它们可以优化查询，但不能覆盖当前状态。

## 状态变化

变化请求应包含目标、预期前值或版本、候选后值、来源事件、规则依据和可见性影响。Validator 组织 schema、领域不变量、引用、权限和跨领域一致性检查。通过后，状态变化、事件和裁定记录原子提交并产生新版本。

## 冲突与并发

提交采用版本检查。同一旧版本产生的两个互斥结果不能都成功；失败方读取新版本后重新评估。模型基于过期 Prompt 生成的候选不得直接应用。读档或切换分支后，绑定旧分支的待处理写入全部失效。

## 投影与重建

领域视图可以从状态或事件建立，并记录来源版本。快照用于缩短重放时间，不改变事件语义。恢复时载入可信快照、验证状态哈希，再重放之后事件；无法验证时回退到更早检查点。

## 一致性要求

- 不允许部分提交跨领域结果。
- 已提交状态必须存在对应事件或明确的初始化来源。
- 派生视图落后可以暂时不可用，但不得返回为最新事实。
- 修复错误使用更正事件或新分支，不直接编辑历史状态。
- 状态与叙事冲突时保持状态，纠正叙事或报告异常。

## 失败处理

校验失败不写入；提交中断整体回滚；哈希不符停止恢复；未知内容或规则版本进入兼容性处理。系统宁可暂停需要该事实的操作，也不从自然语言猜测权威状态。
