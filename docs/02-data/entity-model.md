# 实体模型

## 目标

实体模型为角色、NPC、道具、场景、地点和剧情对象提供稳定身份与共同来源语义。它描述逻辑边界，不规定数据库表或继承体系。

## 身份与类型

每个正式实体拥有在战役内稳定且不可复用的 `entity_id`、实体类型、定义来源和创建事件。显示名称可以重复或变化，不能作为引用键。类型决定由哪个领域模块校验其状态；跨类型通用字段仅限身份、来源、版本和可见性等真正共享的内容。

## 定义与运行状态

- **Definition**：内容包提供的相对稳定设定，如基础身份、道具模板、场景结构和剧情节点定义。
- **Entity State**：战役中由事件造成的当前状态，如位置、伤势、持有者、关系和可用性。
- **Derived View**：为查询或模型任务生成的受限视图，可重建且不构成事实源。

原始定义不因游玩直接改写。需要覆盖或扩展内容时，应记录扩展来源和适用战役；运行时变化写入状态与事件。

## 来源与版本

实体及重要字段应能追溯到内容定义、导入材料、玩家确认或已提交事件。AI 补充内容必须标记为生成候选，经确认与校验后才能成为正式定义或状态。每次状态提交递增对应版本，并保留产生变化的事件引用。

## 引用与生命周期

实体之间通过 ID 引用。创建、激活、停用、销毁、死亡或退出场景都是显式状态或事件，不能通过删除记录表达。历史引用必须继续可解析；真正清除只适用于从未提交的草稿或可重建缓存。

## 可见性

实体存在、字段和关系可以拥有不同可见范围。查询时生成面向玩家、特定 NPC、GM 叙事或幕后任务的最小视图，不能因某任务可见就把完整实体公开给其他任务。

## 一致性要求

- ID 唯一且不复用；同名实体不自动合并。
- 状态变化必须引用原因事件和前值版本。
- 引用目标不存在或类型不符时拒绝提交。
- 一个事实只由所属领域的权威状态表达；其他领域保存引用或派生视图。
- 定义、当前状态和历史事件冲突时，不静默改写任何一方，进入内容或状态异常处理。
