# 事件模型

## 定位

事件记录战役中已经提交的事实变化及其因果，是重放、审计、记忆和分支的共同历史依据。事件一旦提交不可原地修改或删除。

## 事件边界

正式事件至少绑定事件 ID、事件类型、分支、顺序、回合、提交后的状态版本、发生时间、来源主体、原因引用、受影响实体和公开范围。不同领域可以扩展载荷，但必须保留共同的追溯语义。

玩家输入、AI 候选和被拒绝变化不是已发生的领域事实。它们可以进入诊断或提案记录，但只有通过校验并随状态原子提交的结果才进入正式事件流。

## 因果与顺序

事件可以引用玩家行动、规则裁定、随机记录、前置事件、时间触发或剧本节点。分支内提交顺序是确定的；墙上时钟只用于展示和诊断，不能代替逻辑顺序。跨领域的同一结果共享事务或因果组，避免出现无法解释的半个结果。

## 规则与随机证据

涉及规则的事件引用采用的 Rule Pack 版本、输入状态、规则结果和修正。随机结果记录种子、骰式或算法标识及输出，使相同输入能够复核。叙事重试不得产生新的规则或随机事件。

## 更正与撤销

错误通过更正、补偿或新分支处理，原事件仍保留。更正事件说明目标事件、原因、授权来源和产生的新状态；它不会声称原事件从未存在。回滚只是选择历史检查点建立新的活动时间线。

## 重放与幂等

事件处理器按分支和顺序重放，并验证前置状态版本。相同事件 ID 或相同提交幂等键不得重复应用。未知事件版本、缺少引用或状态哈希不符时停止重放并报告，不猜测迁移结果。

## 可见性

事件事实、玩家可见描述和幕后载荷可以分层。Event Log 保存完整授权数据；对外日志和模型上下文只读取 Visibility Policy 允许的投影。
